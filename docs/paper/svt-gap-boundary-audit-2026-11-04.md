## Exact family and accounting

This establishes the **registered search boundary**, not an independently executed test of the installed binary's entire API. The frozen family has scale divisor 2, coded 960×544, full 240-frame source, 8-bit limited-range input, SVT preset 4, `--rc 0`, `--keyint -1`, and pinned encoder, ffmpeg and dav1d identities. The saved windows' native rate is 50 fps, and the scores use the 80 ticks 0, 3, …, 237. Exact manifest/source identities and saved command/control details are in the score summaries; the historical rate-search jobs were `20261031T111927Z-2d513709` and `20261031T105514Z-2310cf5a`.

The signed configuration value is `offset=-20`, **outside=true**: source-derived player region R is resized to coded size, every 64×64 block touched by R receives offset 0, and every other block receives +20, not −20 inside. The apparent `o20` name encodes the magnitude, not a −20 change applied to player blocks. The original map and 240-frame inputs must remain identical. `s2_o0` and `s4_o0` are different frozen anchor families; a different scale, offset, preset, encoder, target convention or map is a new family and must not be presented as a repaired `s2_o20` sample. See [ROI/search rules](../../experiments/tennis/w1_roi.py), [native encode](../../experiments/tennis/w1_encode.py), [native command](../../src/codecs/svtav1.py), and [W7 spec](../../experiments/tennis/w7_specs.py).

Rates use **complete IVF file bytes**, including the 32-byte file header and 12-byte frame headers: for 240 frames, 2,912 bytes, or 4.853333 kbps at 50 fps. The code separately stores payload bytes but `rate_kbps` charges IVF bytes for anchors. Switching only these two anchors to payload bytes would change the accounting convention and create an artificial bracket, not a valid repair. The hybrid target is the corrected total KPS2 rate including modeled 12-reference bank and adapter accounting, not merely its native base stream. Anchor and target need their existing respective complete-rate contracts.

No missing-family score may be extrapolated; [W7 analysis](../../experiments/tennis/w7_analysis.py) uses measured bracketing points only.
2. If a bounded new rate-only probe is scientifically worthwhile, **freeze before seeing it** one or a few integer CRFs within 1–69, beginning with 69 as the nearest possible neighbor to the observed boundary, using exactly the original recipe, source/ROI identities, 240 frames and full IVF accounting, with matching control/decode checks. This tests for a non-monotone exception; a failure at 69 does not prove none at 1–68. Neither the original `next_crf` search nor a single 69 encode can establish a mathematical minimum across all integer CRFs. A sweep of all unmeasured CRFs would be a separate explicit cost/benefit decision and cannot be justified as the automatic next step.
3. If a verified same-family rate falls below target, identify a verified above-target point, independently check archives, exact rate and decoded frame hashes, then score both at the same 80 ticks using the original region, judges, versions and controls. The actual scorer currently selects search brackets; a nonmonotone exception needs a reviewed explicit-point scoring path, rather than falsely marking the monotone search as complete. Interpolate only on a real scored bracket at the corrected target and recompute intervals with unchanged billing. If no lower point is found within the registered budget, stop with the family unresolved; do not infer the result of untested points.

It cannot repair the original `s2_o20` family or eliminate the dropped DCVC omission. A comparison on measured support at a different common rate is a distinct, labeled analysis; never extrapolate to the corrected target. Any new encoding/scoring follows a recorded rule, validated source and tools, smoke, independent audit and a reviewed finite budget.
