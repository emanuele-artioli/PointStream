## Role in the paper

A single received stream can serve a viewer and a sports-analysis application. The display figures evaluate the reconstructed play. The machine panels ask whether an application can locate the ball or recover a player's pose or silhouette. A receiver can read transmitted points directly; a conventional video receiver can run a task model on its decoded pictures. Include a PointStream RGB-only arm to isolate what survives rendering, and a separate direct-output arm to show what the syntax exposes. Use the same independent human reference and full delivery rate for the two uses. A machine-only mode that discards the display video would have a different byte bill and warrants a separate study only if claimed. This framing follows the human- and machine-consumption use cases described by [MPEG Video Coding for Machines](https://www.mpeg.org/standards/MPEG-AI/2/).

## Matched-rate experiment specification

The planned figure plots task accuracy against total delivered bitrate for the same source frames. It asks whether points already delivered for playback give an analytics application a more accurate or cheaper way to recover player state than analysis of ordinary decoded video. The hypothesis is that decoded low-rate video loses detail needed by the estimators while transmitted points retain usable pose. The competing explanations are that sender estimation errors dominate, conventional decodes retain enough detail, or the receiver mask requires enough model computation that it offers little practical advantage. A result at one rate does not imply a win across rates or domains.

Start with the existing 12 reviewed frames as a development pilot and all 24 player masks. They are from one opened rally, nine frames have model-assisted source labels, and all contain two visible players. Preserve these annotation strata and collect independent source-only joint labels before evaluating accuracy. The 303 kbps native AV1 and AV1-plus-ball decodes provide an immediate paired RGB control; they do not by themselves compare a complete PointStream stream at that same rate. The planned 20/50/125 kbps joint-rate experiment must provide complete, matched-duration delivered streams for the primary comparison. An absent, occluded or missed player is scored as such rather than excluded. Freeze selected samples and correspondence before viewing predictions. A pilot requires verified local access to the decoded frames, source labels, model weights and sender/receiver outputs; record their hashes and all missing inputs before running models.

For every matched-rate point, compare AV1, effective ROI AV1, DCVC-UF and complete PointStream at their actual total delivered bitrates and on the same native frames. Report the available source image as an estimator reference. Score two PointStream interfaces independently: (1) the decoded transmitted keypoints with their visibility and identity, if available in the paid receiver bitstream, and (2) the receiver-generated compositing silhouette, if it can actually be made available to an application with the counted inputs. The current IoU numbers use the latter projected mask and do not establish that a mask is transmitted. Run the same fixed image-based estimators on the decoded RGB of **every** arm, including PointStream. Do not supply source boxes, labels, sender tracks or PointStream masks to the RGB-only arm.

Use YOLO26 instance segmentation and YOLO26 pose as the first practical RGB baselines, with model size, checkpoint, preprocessing, confidence and association rules frozen. Include the already used YOLO11x-pose as a second pose baseline where available. SAM 3.1 is a useful stronger alternative, but it requires an explicit prompt policy. For a practical automated SAM 3.1 comparison, use the same text prompt or boxes from the same frozen detector operating on each decoded frame, and count the detector's misses. A separately labeled oracle-box experiment can diagnose segmentation conditional on localization, using identical source-derived boxes for all decodes; it cannot stand in for an end-to-end unprompted result. Where tracked video mode is tested, apply the same permitted initialization and subsequent input policy to every arm, including startup cost and latency. Verify checkpoints, software versions, model exposure and actual runtime before choosing which models fit the pilot. [Ultralytics YOLO26](https://docs.ultralytics.com/models/yolo26/) · [Meta SAM 3.1](https://ai.meta.com/blog/segment-anything-model-3/)

Evaluate masks with instance IoU against the reviewed body-only masks, count an unmatched visible player as zero IoU, and separately report player recall and false positives on absent frames. Define association using a frozen source-label matching rule after inference. For pose, use visibility-aware COCO OKS and missed-player/joint counts against independently labeled source keypoints, reporting localized-joint pixel error as a supplement. Keep visibility conventions, scale and missing predictions identical for all arms. One fixed segmentation model and one fixed pose model suffice for the first decision; add another model only if the result's direction or generality remains uncertain. Measure per-frame or per-clip inference wall time, GPU type, memory and warm-up separately from codec bitrate. Include extraction already needed at the sender and receiver, amortized model installation assumptions, transfer of any model or reference data, and actual end-to-end latency when claiming computational savings. A direct pose can avoid a separate RGB pose pass, but its sender extraction and any reconstruction compute are still real costs.

The decision is to retain the machine-task contribution as a demonstrated comparative result only if direct receiver data scores better at a comparable complete rate than a credible decoded-video estimator on held-out matches, with misses and costs visible. If the direct data is weaker, report it as an accessible interface and use the RGB task results to assess whether the reconstructed video supports analytics. Freeze the setting and model after the development pilot, then repeat on multiple previously unopened matches with source-only labels and report match-level paired results and uncertainty. The exact GPU/CPU budget and fleet manifest must be sized from a representative smoke before dispatch, with all earlier allocations accounted for.
