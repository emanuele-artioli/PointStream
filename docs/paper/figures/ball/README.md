# Ball figures

These are figure drafts built directly from stored numeric experiment results. PNGs support author review. PDFs are vector graphics for manuscript layout. Each panel names its rate and experimental scope. They answer different questions and do not share a source clip.

- **[Nearly equal-rate ball fidelity](matched-rate-ball-fidelity.pdf)** compares AV1 and AV1 plus tracked source-pixel tiles at 303.425 and 303.710 kbps. The ball crop is 64×64 native pixels. Player scores use source-reviewed body masks. The 12 same-frame, full-size RGB observations were selected from one 240-frame 50-fps Nadal–Kyrgios development rally. Whole-frame PSNR includes the ball. The candidate adds tiles on 195 of 240 frames. [Rates and full-frame quality](../../../experiments/matched-ball-rate-20261122/render-result.json) · [Candidate object quality](../../../experiments/matched-ball-rate-20261122/scores.json) · [Plain AV1 object quality](../../../experiments/clean-court-regional-screen-20261118/control-scores.json)
- **[Ball detection](ball-detection.pdf)** shows the paired WASB detection replay on game9/Clip5 at a 10-pixel tolerance. Visible and absent-frame percentages have separate denominators. One uncertain frame is excluded. The AV1-plus-streak stream uses 64.085 kbps versus 63.058 kbps for plain AV1, a 1.63% increase. This figure depicts rendered streaks; it does not evaluate the tracked-pixel sidecar in the first figure. The planned matched-rate rerun and confirmation across sources remain necessary to establish generality. [Per-frame replay summary](../../../experiments/matched-ball-rate-20261122/historical-detection-replay.json) · [Rate provenance](../../../experiments/k5d-inputs/saved292-rescue-absence-analysis-root-acceptance-20261113.json)
- **[Three-match ball BD-rate](three-match-ball-bd-rate.pdf)** shows equal-source average and individual match effects from saved, paid tracked-pixel experiments against the achievable baseline envelope. Their combined labels include 32 visible instants. This is a separate experiment from both figures above and the sample contains three physical matches. The bars report the saved PCHIP equal-quality rates rather than extrapolating the matched-point diagnostic. [Three-match analysis](../../../experiments/submission-ladder-ball-confirmation-analysis-20261115.json)

Run `MPLBACKEND=Agg python docs/paper/figures/ball/plot.py` from any directory to regenerate all six files. The script reads the receipts and asserts the sample counts and packet byte totals before plotting. Figures require Matplotlib and use DejaVu Sans. These plots visualize existing measurements; no media or new inference is bundled.


## Rate–quality and detection curves

[Three-match ball rate–quality](ball-three-match-rates.pdf) replots all physical SVT, effective fitted ROI, DCVC-UF and tracked-pixel packet points against complete delivered kbps. Markers distinguish the three matches. Each line is the equal-match average of PCHIP interpolation over the intersection of all three measured source ranges for that single method. The 25, 60 and 25 fps native timelines determine packet rates, with 64, 154 and 64 frames respectively. The physical source rows include 9, 11 and 12 visible labels. Read each match's background and training exposure in the [confirmation analysis](../../../experiments/submission-ladder-ball-confirmation-analysis-20261115.json). This chart contains no extrapolation. On these very short samples the three-match-average PointStream and AV1 support only overlaps at **371.94–375.14 kbps**. Neither curve establishes what happens at 20–125 kbps. The existing -26.28% equal-quality three-match BD-rate uses per-match achievable anchor envelopes and is the more informative existing comparison.

[Ball appearance versus rate](ball-streak-rates.pdf) and [detection versus rate](ball-detection-rates.pdf) show all three saved operating points on the game9/Clip5 retrospective clip. The first uses ball-crop DISTS and the second uses WASB on decoded frames. Points use actual packet bytes, including the baseline PSBL wrapper. The paired bitrate gaps range from 0.4% to 1.63%. Labels show hits among 261 visible frames and false detections on 30 absent frames. An uncertain frame is excluded. The 63.06 versus 64.08 kbps point uses a rendered streak and remains a different representation and source from the three-match tracked-pixel points. The lower-base trial is registered [here](../../../experiments/ball-matched-low-20261122/README.md). It holds the fitted streak fixed as an initial pilot and will measure whether a source-refit changes the result.

Build with `MPLBACKEND=Agg python docs/paper/figures/ball/pooled_rates.py` and `MPLBACKEND=Agg python docs/paper/figures/ball/detection_rates.py`. The former authenticates the accepted full analysis hash and assigns rates from the frozen implementation's source-specific FPS. The latter uses the [compact, archived rate context](detection-rate-context.json) extracted from the SHA-256-authenticated accepted 292-frame analysis archive and joins it to the frozen detector scores by CRF and producer job.

## Matched-rate machine use

[Ball localization at nearly equal total rate](matched-low-detection.pdf) reports the complete 292-frame game9/Clip5 test. At 63.058 kbps, a fixed WASB model on decoded plain AV1 localized 5/261 visible ball frames within 10 pixels, with 3/30 false detections on absent frames. At 63.354 kbps the same model on the fixed-streak decode localized 239/261, with 11/30 false detections. At 63.364 kbps it localized 235/261 with 11/30 false detections using the source-refitted streak. The source-refitted packet itself supplies 240/261 locations within 10 pixels and a location on 2/30 absent frames. A source-only sender fits the centers. Each denominator is explicit. This is one retrospective clip and the paid candidates use VBR base encoding while the baseline uses CRF. The comparison is nearly, rather than exactly, equal rate: candidates are 0.471% and 0.486% larger. The sender's source exposure, 30 absence frames and judge model training provenance restrict generalization.

The second direct payload, generated by keeping the original fitted positions, gives 239/261 and 2/30 absent false. At 5 pixels both direct tracks give 205/261. The fixed and refitted WASB calls give 229/261 and 226/261 respectively at 5 pixels. False detections from decoded frames are substantially more frequent than for direct refitted positions on this clip. A source-held-out development set is needed to choose a different detector operating point. The stored WASB outputs do not include raw confidence or heatmaps, so no ROC follows from these results.
