# Explaining the scene-selective codec

The [architecture figure](architecture.pdf) shows the complete intended sender-to-viewer design. It is a vector diagram suitable for the system section. The scene-and-rate decision leads either to object and background coding or to the conventional full-frame path. Both paths preserve timestamps and reach the same presentation stage. Valid player appearance and court references remain at the receiver across a conventional-coded shot. Sending the first state, refreshing it and switching modes all consume bytes.

Suggested caption. **PointStream system architecture.** The server identifies shot boundaries and selects a coding representation using scene content, receiver state and available bitrate. Eligible shots transmit compact foreground signals, appearance information and recovered-background updates. Conventional coding handles other or uncertain shots. The receiver reconstructs the selected representation, retains valid reusable state and presents a continuous timeline. A 226.1-second receiver replay covers two object-coded visits and the conventional footage between them. Its route was selected for the experiment. Automatic bitrate selection remains an application of the measured curves. [Two-visit receiver replay](../../../experiments/cumulative-joint-20261122/README.md)

## Passage to accompany the introduction timeline

MPEG-4 sprite coding already represented a background as a mosaic that the decoder could warp as the camera moved. Static sprites required construction and initial delivery of the mosaic. Online approaches addressed foreground rejection and the cost of signaling shape. Modern AV1 encoders can retain decoded pictures in reference buffers and choose how to refresh them. A broadcast cut therefore need not erase all predictive context, although a displayed keyframe refreshes the reference slots. These are engineering constraints a deployment must address. Evidence about implementation costs does not establish historical adoption rates. [Sprite-based video coding using on-line segmentation](https://www.researchgate.net/publication/3747070_Sprite-based_video_coding_using_on-line_segmentation) · [AV1 specification](https://aomediacodec.github.io/av1-spec/av1-spec.pdf) · [Reference encoder refresh policy](https://aomedia.googlesource.com/aom/+/0c164bfcabb8d3ab5eda43738d52a047735fe6d1/av1/encoder/encode_strategy.c)

PointStream tests a different decision on return to play. The receiver can keep an explicitly identified court reference and player appearance while displaying a conventional cutaway; the server can refresh each asset independently. On one fixed-initialization transition, inter-coding the return plate saved 24.19% of its marginal bytes and 2.24% of the complete background-only packet at equal return-plate quality. That comparison uses a fresh plate as anchor. To establish an advantage over native prediction, compare continuous conventional encoding with its normal references, an explicitly preserved pre-cut reference, and the PointStream return on the same frames. Charge the initial court, cutaway, updates and any random-access refresh; score the full passage as well as the return.
