# Explaining the scene-selective codec

The [architecture figure](architecture.pdf) shows the complete intended sender-to-viewer design. It is a vector diagram suitable for the system section. The scene-and-rate decision leads either to object and background coding or to the conventional full-frame path. Both paths preserve timestamps and reach the same presentation stage. Valid player appearance and court references remain at the receiver across a conventional-coded shot. Sending the first state, refreshing it and switching modes all consume bytes.

Suggested caption. **PointStream system architecture.** The server identifies shot boundaries and selects a coding representation using scene content, receiver state and available bitrate. Eligible shots transmit compact foreground signals, appearance information and recovered-background updates. Conventional coding handles other or uncertain shots. The receiver reconstructs the selected representation, retains valid reusable state and presents a continuous timeline. The diagram specifies the complete design. Component experiments establish its individual coding behaviors, while the rate-selection rule and complete mixed-codec passage need their corresponding joint evaluation.
