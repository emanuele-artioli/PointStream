# Prospective SVT container oracle — 2026-11-04

This separately versioned achievable-transport study asks whether losslessly remuxing an existing native AV1 IVF stream into Matroska saves enough **complete container bytes** to cross a corrected W7 target. The original IVF anchor, its unbracketed `s2_o20` status, and user-dropped med000 DCVC remain unchanged. No saving, native test, new rate-quality point or benchmark closure has been established. This proposal does not use or replay the interrupted native archive listing.

`python -m experiments.tennis.w7_remux_oracle --help` specifies the proposed one-stream worker: all paths, hashes, frame count, FPS and geometry are explicit. It verifies input and ffmpeg/ffprobe SHA256; creates a fresh work directory without overwrite; runs ffmpeg with single threads, `-map 0:v:0 -c:v copy -fps_mode passthrough -f matroska`; probes every original and remux frame with ffprobe; and decodes each using ffmpeg with explicit CPU-only `-hwaccel none -c:v libdav1d` into yuv420p. It requires AV1, the registered geometry, FPS, color metadata, exact frame count, exact rational frame timestamps/cadence and identical full decoded YUV bytes. Distinct numerical time bases are permitted only when all time points match exactly. Full IVF/MKV byte sizes, actual rates, SHA256s, source/binary identities, commands, stderr and resource usage are kept. There is no encoder, Torch, source video or GPU in this operation. Unknown/missing metadata and unsupported timestamp behavior fail closed, even if a looser remux could be visually equivalent.

An optional historical decoded-YUV SHA verifies whether this exact native stream's ffmpeg decode reproduces the pixels used by the old quality scorer; a mismatch fails. Without this proof, saved quality cannot be reused. An independent, pinned dav1d decode or fresh scoring may be needed to qualify reuse; no decoder parity is inferred merely from AV1 conformance. To claim a newly defined cross-family comparison, remux and audit **all selected SVT anchor points** under the same transport convention, not only the two favorable cases; newly unscored points still need scoring and a real bracket. Record the transport and model/overhead conventions alongside the corrected hybrid total rate, and do not subtract IVF headers from only some rates or relabel the historical result as repaired.

Before any execution, a fleet or supervised local admission must verify exact input archive/stream and original decoded hash without replaying an uncertain submission, authenticate the ffmpeg/ffprobe binary and decoder builds, choose an explicit separate local filesystem/work directory, set `CUDA_VISIBLE_DEVICES` empty, assert exclusive one-CPU affinity and preserve all failed artifacts. The worker's individual subprocess timeouts are not an aggregate budget: the supervisor must enforce a prospective **120 workload CPU-seconds total, zero GPU**, with hard wall deadline and child-process cleanup, including staging, both probes and decodes, audit and failure reserve. This cap is a proposal, not an authorization or cost prediction. The source-free test begins on the two CRF 70 streams only after their identities are independently established. A valid result still needs a separately planned same-transport bracket and scoring if the original rate-only search omitted the point.

The commands and acceptance rules remain subject to root review and a real environment smoke. In particular, IVF may lack explicit color metadata or precise Matroska timebase support; the present strict checks will stop rather than silently invent metadata. CPU-only contract tests mock metadata and verify copy-only commands, no-overwrite flags, rate cadence, color mismatches, and SHA failures; they are not native codec evidence.
