# Midyear PointStream code lineage outside the late PR net-diff record

## Scope and evidence rules

This record covers the uncovered code history from 26 March through 29 July 2026, including direct commits and the older PR #11–17 work that crosses those stages. The source is the immutable bare repository at `/private/tmp/pointstream-recovery-20260930/source/code.git`, checked against `all-code-commits.json` and `github-prs.json`; exact SHA and per-commit stage membership are in [midyear-direct-dispositions.json](midyear-direct-dispositions.json). It complements the existing PR #73–149 net-diff record and the Aug 20–24 contract/reconstruction record. It does not repeat the latter’s metric calibration, object-stream contract, lattice, and delivery-accounting findings.

The entries below follow actual changed files and behavior, not commit subjects. I inspected the main code paths and the contemporaneous committed reports where present. I did not train models, run GPU jobs, reproduce historical encodes, or modify the checkout. Unit tests establish implementation-level properties, not visual fidelity, rate-distortion superiority, held-out generalization, or paper-grade measurements. Historical metrics cited below are what the committed report says; their referenced inputs and output trees are not bundled in this bare repository, so they were not independently recalculated.

## April: first object/residual loop

The March 26–April 21 ancestry leading to PR #11 is the first retained semantic-pipeline implementation in this recovery slice. The key steps are `a6a605410e2dd665186f33fe802c87d6cc71effc`, `f06fc9420c616c2424709f4e3a0bab928f47be5f`, `a3cd75a9cdc8d893083335ef4755e04fb5ad7b17`, `b383588c9528c451eee22ddd59f6ff4d8cfb1f57`, and `4b8ebb899d3336cf7905ed1877282aea2b1cecd3`.

`a6a6054` implements a player/racket binary importance map and residual generation. It subtracts the synthesized prediction from the source, multiplies the signed difference by the actor mask, offsets by 128, clamps to an 8-bit range, then encodes a YUV420 `libx265` stream (CRF 28, medium). `f06fc94` adds the decoder-side inverse convention—decode, subtract 128, add to the predicted frame and clamp—and stores the residual by path through the disk transport. This is a prototype correction stream, with lossy chroma/quantization and signed-range saturation; the residual tests do not establish a lossless round trip or wire-serializable client. The initial `ResidualCalculator` also materializes the source sequence and writes a project-relative default output, both later engineering concerns.

`a3cd75a` adds a ball detector that warps the panorama into each frame, removes pixels under known actor masks, thresholds the remaining mean absolute difference, and takes the largest connected component as a ball center. It emits a per-frame coordinate/velocity and keyframe or interpolation event. This is a hand-built detector that has no learned association or calibrated ball-visibility result; on an occlusion it carries the previous coordinates and sets velocity to zero. `b383588` extracts a JPEG reference for each player track by selecting the largest detected box (tie-break toward frame center), adding 10% padding, and JPEG-encoding at quality 75. This produces appearance bytes and a track identifier but does not independently verify track identity or choose a temporally representative view.

`4b8ebb8` wires a Diffusers/OpenPose ControlNet strategy and an AnimateAnyone wrapper alongside a mock compositor. Its unit tests use a fake diffusion pipeline or stub runtime; they verify tensor conversion and invocation, not model output. The baseline ControlNet supplies the reference crop as its img2img initialization and a rendered pose as ControlNet conditioning. `70c0b523d52c8d297f5d6ce148dd1364bd4b2eba` adds a local AnimateAnyone runtime adapter and crops/resizes pose/reference inputs, but still only demonstrates model integration in code. Neither integration commit records a qualified trained checkpoint or a coded-video comparison.

`93d03064177ff736733928f4d07dbbdfff69efdf` adds binary-mask metadata codecs: run-length encoding, zlib-compressed bit packing, PNG, plus a quantized polygon representation. The default auto choice compares RLE and packed bytes; polygon is explicitly selected. Its benchmark script runs the pipeline for requested mask codecs and reads the byte ledger and actual codec counts, but the code addition itself is not a benchmark result. The reported unit tests cover encode/decode and transport plumbing. PR #12’s `b2dc8f852c975205c914dc5cd10839597a53a1c0` moves the compositor toward post-generation client segmentation and changes the background modeler to an actor-exclusion masked median; tests exercise mask exclusion and synchronization. This is an implementation choice for one background estimator, not evidence that its mask or median is accurate on a match.

PR #11’s merge on April 22 (`32c4c1cc278fa7eaceae99e1fbdd6ede4cd5f949`) and PR #12’s backup merge (`dda976aa180c39790b502256444bbe65bf09ccc3`) are ancestry/packaging boundaries, not extra experiments. PR #11 includes coverage/CI and test additions; PR #12 is explicitly a backup-main recovery with tests and dependency cleanup. The April 22 direct commits consolidate dependencies and add the actor-exclusion background change; they do not encode a new result. The large retained tests in this period are mostly mock/pure-code tests and should be described that way.

## May: residual modes, temporal generation, and measurement scaffolding

The most consequential residual change is `97a5da05c836024c535ee0b05c9a2ec4252c7d83`: `ResidualMode` defines `none`, `players_only`, and `full_video`. The first omits residual work, the second masks error to actors, and the third reconstructs the whole frame (optionally running server-side GenAI) before creating a whole-frame residual. Both coded modes use a lossy video stream and the centered 8-bit residual representation; the full-frame option makes the correction signal explicit but is not itself a rate or quality result. `8d859ae9f0a78098f2b3976fca44bcd627def82e` records and fixes a real temporal bug: the renderer used future pose lookahead, causing actor synthesis to lead the source and leave a shadow correction burden. The change aligns synthesis to the current frame. It is a correctness repair, not a model-quality comparison.

`905a3b16729860f598b8fda2bc76000de942723b` adds adaptive background downscaling to residuals: it separates the player-mask region, downsamples the remaining difference, and upsamples it for encoding. `3ef55fd7420ce0b0d6db6f12927d742e28c24d99` adds keyframe-only GenAI processing controls and a separate residual path, making compute and correction cadence configurable. These controls create ablation dimensions; there is no contemporaneous evidence here that either setting wins after full bytes and delivered reconstruction are compared.

`1ac9e0a5552ef83c3af6d6dcadf918a03366c1a9` adds evaluation plumbing for PSNR, SSIM, VMAF, and byte sizes. The implementation pairs decoded frames by order and falls back to nearest timestamps, resizes unequal frames, and invokes external FFmpeg/libvmaf. These are useful mechanics but make metric versions, binary paths, frame synchronization, and crop policy part of the protocol. Later repair history shows those were not safe to assume; do not combine its early SSIM/VMAF or hand-built VGG distances with the calibrated metrics introduced in August.

The later June 11 learned-model commit `ed4844d51e607b1e19480c471cc574ca9d36e2de` adds a Pix2Pix U-Net strategy, a pair-dataset builder, and a GAN trainer with adversarial, VGG-feature, and pixel losses. The inference path constructs a pose condition and also concatenates a resized reference crop into the six-channel generator input. That wiring and its tests show a custom conditional generator is implemented, not that it reproduces identity or improves the codec. Training and validation splits and a held-out match are not established by this code commit. Other pipeline commits add multi-profile config, keyframe processing, YOLO26 selection, adaptive background controls, and metric/profiling switches (`03ed11eb…`, `47f55e50…`, `98987e06…`, `3ef55fd…`, `f8f137ce…`); these are configuration and pipeline evolution rather than independent scientific outcomes.

## June: structured actor pipeline and tennis-specific data/model branch

The June 8 rewrite (`14be71785741962906a146e0a244cd19b310758a`, followed by `245fe93e15e609d68ef75caf21d142c36b4b9357` and `b2617d69fd44f6e9b4ec7652c857caa20d045418`) introduces a structured actor pipeline and moves runtime choices from ambient environment variables into explicit configuration injection. This is an architectural and testability change; it is not an encoder improvement. The June 9–10 batch then integrates the Moore- AnimateAnyone layout, pose ControlNet, Canny/segmentation controls, IP-Adapter, mask-hull fallback, metadata boxes, and debug exports. Representative implementation commits are `7928dbea533db48dd097a86237525eb9f4510bca`, `3ad3184166e6a210f14767fa9dbf977510e6b9b8`, `e1f5b076db536df05e5a98d19ad96e390fc7952b`, `bd3bd3dfb72279bfba86687e526b857fdf77a78f`, `902ed439b0b798510f13cdffbaed1453500509a2`, and `2eae67c090c421c3beb372a6d170e2879fc753d1`. Backend choice and configuration support are implementation; fake-pipeline tests cannot validate real checkpoint behavior. The immediate IP-Adapter parameter removal (`e14fd61…`) and repeated module/mock refactors mean not every named backend is a stable supported experiment.

The June 11 Pix2Pix engine is accompanied by a separate SPADE-for-tennis branch, which arrives in `43de74bff70564c0bc114fa9452bba9898ac4cac`: a SPADE-conditioned ResNet-9 generator, a light reference encoder, GAN discriminator, and training runner with feature-matching, VGG, and L1 losses. The code constructs pose and reference tensors separately and uses the reference encoder to condition spatially adaptive normalization. `TennisSkeletonDataset` chooses a random reference from the same player/subset, with no exclusion of the target frame in this revision; training has no explicit held-out video validation split in the inspected runner. The initial data transform resizes concatenated pose/reference/target strips to fixed dimensions, while `e6b15d025eee8fa15bfd9391aafe87b75d6f7d30` changes to hierarchical folders and synchronized square padding. `2364156fa4978e4805a5d0d451c4e044a12ed905` adds dataset metadata and inference smoke tooling. These are useful reproducibility corrections, but the commits establish only trainability/inference scaffolding; no robust held-out identity/quality result is recorded here.

The tennis corpus pipeline starts with `10a75a33dff7514f365248f8372973f62d86fb12` and is revised through `fc7cee50d39da8a825e410dce2157a0d1282939d`, `6d1c236054811155e2f9d8d462be204737ddcc6b`, `bd955097d2750d237088ddff4b6e07ca668be7ec`, and `b1127f6dd5a5af0d6c6ba8ad865f4221bb3e1801`. It extracts scene scores/cuts, then classifies and segments tracks; the dynamic classifier finds scene-score peaks using a prominence derived from global median plus standard deviation, validates short-neighbor cuts with a low-resolution HSV histogram, clusters duration/motion statistics using robust scaling, PCA, and GMM/BIC, and calls the highest motion-variance cluster a replay candidate. These are hand-set, data-dependent heuristics, not labeled ground truth or measured cut/replay accuracy. The segmentation script uses detector outputs and track heuristics to select players/rackets, combine object crops/masks, and generate pose. There is no audit demonstrating completeness or identity purity of the derived corpus.

`5c73bb94285b2cded41901853306af593fc1c7ff`, `d9bd7c48186269342ddb4715419303b8f7c86b60`, and `8d1d120d6dd2bbe0d45dcffb4b6551356e5295b2` develop racket visualization/pose conditioning. The heuristic chooses a wrist by proximity to the detected racket-box center (or a supplied dominant hand), estimates handle/shaft/head from the wrist and box or mask extrema, and linearly interpolates missing racket boxes. It does not infer a fully observed physical racket pose; errors in detection, wrist side, or mask shape feed the rendered skeleton. The latter commit also removes an older dataset script, so the sequence is iterative tooling, not independent candidate rows.

## July: measurement corrections, low-rate controls, and bounded learned-codec tests

July starts with a different question: whether semantic prediction plus a residual saves bytes after real codec decode. `60afba8f853b00bf6ab89b4a89bd2a2dde2aee0d` adds the residual-variant matrix harness. Its first 3-frame smoke was misleading because the server compared against an in-memory panorama while the client consumed a lossy encoded panorama. `465eb713234bf4e6f409b0ab52e5686d960a1e4c` corrects symmetry by computing the residual against the panorama’s round-tripped decode and transporting those exact bytes; it also repairs null PSNR. The reported corrected three-frame smoke is still negative: at q50/q90, residuals of 226,563/185,931 B were added to 528,077 semantic bytes, for net +487,445 B, with PSNR 23.879/23.860 dB. This is a smoke only, and SSIM/VMAF were null in that table. `dd761c34be18e7550b76b23f637d10acc788e21e` adds explicit FFmpeg scaling for dimension mismatch. The result supports “this short test costs more,” not general ineffectiveness.

The later report records a 60-frame residual-only matrix on `real_tennis.mp4`, using `libx264` because `libsvtav1` silently down-converted requested pixel formats in the tested build. At threshold zero, yuv444p was 2,272,729 B / PSNR 32.396 / SSIM .939 / VMAF 71.621; yuv420p was 2,160,007 B / 31.540 / .938 / 71.620; gray was 2,152,428 B / 31.522 / .929 / 72.318. The `threshold=1` cells saved only 2,536 B in yuv444p and were larger than threshold zero in yuv420p/gray. This is a single clip and residual-only format test, not a full semantic codec comparison; the default AV1 path did not honor the intended pixel-format ablation. A separate AV1/HEVC baseline sweep (`da62a2837cf25dcfeb5aaf8b94435cd64e55e1fa`) corrects an initial short/preset-mismatched setup to 60 frames and slower presets. Its matched-VMAF anchors report AV1 savings of roughly 5–32% at lower rates and parity near the very-high-quality `veryslow` point. That is one input clip with conventional codecs only; it is not evidence for PointStream.

`6f82e219116e9010177019b3a9504dcafc1cbfcf` extracts runtime scene classification; `9cf3012458888d4118c8becc03098f8e1e62ac99` adds full-match scene routing, selecting semantic vs fallback by outcome/bytes; and `7d677f301510eaeafcaca16663948d586f3f851a` adds complexity tiers, real-time-factor fields, and panorama-anchor caching. These are orchestrator/performance mechanisms. The recorded G1 excerpt exposed a frame-index contract bug: extracted clip-local state was being confused with source-global frame IDs. `93c4a1faad52f4712e5f56ddf8e14b838791e132` sets extracted subchunks to zero; `f25fc7b981be90038404b7d34ed1089d17d5b330` fixes the calculator’s source iterator to honor its offset; `3dea9ce23cd3cd6d6f4861db6f989688841f90fa` wires residual config values that had been silently dropped. The commits repair synchronization and knobs, not visual quality. The per-scene cache and profiling changes (`6e9aadc…`, `a1966e…`, `e39640…`, `a1f45c…`) add counters, stop debug PNG writes, choose FFmpeg thread count, and cache pano encodes; no like-for-like timing claim is inferred.

The learned-video comparison is narrow but informative. `7047207bcdb9182efae47c1913b0a3f5b67a74b79` adds a simplified HNeRV-style per-video fit and decoder/embedding serialization. The report for one 60-frame 640×360 clip records 15k epochs, a 3.1M-parameter decoder, 5,939,951 encoded bytes, PSNR 32.502, SSIM .918, VMAF 79.079; the reported AV1/HEVC anchors generally dominate. `411c11b281980c0a110c0ad7849f0e36c19bebad` is a patch-identical duplicate, not a second run. `5418ae7f2c29cbe44b78fcf00c9b458e22de7c7b` adds a weight-residual-coding proposal while invalidating the initial run; the report says dense half-precision weights with 80% zeroing plus gzip still cost about 5 MB. `bf94ce35e90aa15e7744266d6a28b3a14f4055cc` adds int8 weights/sparse residual packing and records .77–.97 byte/parameter and .4–3.5 MB budgets, but VMAF is nonmonotonic (51.04 at .9 MB then 46.15/45.69 at larger budgets despite higher training PSNR). The report flags this anomaly and retracts the broad early “HNeRV uncompetitive” claim. This remains one 60-frame clip, provisional training, and lacks background-layer handling; do not generalize it to all neural video codecs.

July checkpoint/training infrastructure is itself an important caution. `761268e136b1aeefc8d0114248f0972793b401fc` adds probe selection and checkpoint evaluation, but initially reimplemented decoder inference and used pure-noise ControlNet while decoder inference used seeded img2img/reference initialization; it also called VGG feature MSE “LPIPS-like.” Those are invalid cross-path comparisons and uncalibrated values. `60c745ca235fee6d23291cd7b11900ac1bdb9f40` adds a successive-halving trainer; `d75880648e0273036c4f2ad3421b4fef101d7ddd` fixes infrastructure failures being treated as poor quality; `a3edf40e3111ea9c38e20f0bff3101628cd20a99` skips zero-epoch subprocesses. `03a9291a7ce9aaab24dc242179ea073621547432` adds MultiControlNet evaluation, while `da5bf6bc583f6658fdea5a7771fc4ebd9db562fe` documents a condition-source mismatch between eval and decoder. This branch is implementation/testing and explicitly imperfect evaluation; it is not an accepted model sweep.

The July 22 Phase 0 evaluation series is the most consequential correction to candidate ranking before the August rewrite. `bd1a41a28276d468af8aaf6e32ab8624a22e49f3` makes checkpoint evaluation instantiate the decoder’s strategy classes and feed raw keypoints, closing an evaluation/decoder path mismatch. The earlier PSNR 9.76 / VMAF .11 result was generated by the mismatched path and should not be called a model-quality result. `cf97c2070a9f9c6f9075dec8dc5698081bf7ab7f`, `85d6d566488faa81e5c8c7dd92d166ad48b76b2e`, `494dddd8db7fe11e99f7fbc731c62c9a691c8d11`, and `96568ac7d7f92ad679f06745e29944295286f80f` repair dataset identifiers, add absolute filename variants for pose/body vs racket conditions, select the intended condition in training, and make the view rerunnable. The wire distinction is real: body-pose derives from motion state; the racket heuristic condition needs extra geometry. `64cd4dd2607a04016b6b0b6575fcd62333eb4361` letterboxes the reference crop, and `fd3d7224c62de9c97f025e51fb2ce5c2aba45a0c` ensures eval supplies native-sized references so inference performs that resize itself. These are data and parity repairs, not evidence of improved output.

`dc0bd46a8cc4b4a09e6b5378a4f8e8cb326b92e0` changes the training selector’s currency to exact residual bytes rather than a heterogeneous quality composite and adds a high-frequency/equal-MSE diagnostic. Its own notes quantify a material defect: actor crops are padded to 512×512 with 79.1% black pixels, making an all-zero predictor appear to cost 811,630 B versus 1,514,916 B for Pix2Pix. This byte mechanism does not yet produce a valid full-frame ranking; candidate use requires correct full-frame or actor-region costing. The #14 merge `67c5bec2139501cb34759b75f55db2e39bbfd93f` packages this work, and the July 22 WIP stash snapshots (`13a1b7…`, `efa264…`, `f64cd9…`, `c2ede4…`) capture partial tree state rather than accepted experimental evidence. PR #15’s package-splitting commits and the #16/#17 merges are refactor, tooling, and a specific missing-symbol restoration; do not count them as new model/codec results.

## Search boundaries and retractions

The supplied commit metadata contains no code commit dated July 30 through August 19; the next captured sequence begins Aug 20 and is covered by `non-pr-scientific.md`. Therefore there is no early-August direct implementation in this recovery set to analyze. A search of this range found no committed dataset corpus, trained checkpoint, or reproducible raw output tree for the cited reports; historical data/output paths are external or absent from this bare source. This is a limitation of the recovered materials, not proof that the files never existed.

Evidence that should remain retracted or scoped: first residual symmetrization smoke is invalidated by encoded-vs-memory asymmetry; early quality comparisons from mismatched generator routes are invalid; VGG feature MSE was not calibrated LPIPS; the first HNeRV WRC trial was invalidated; thresholding did not establish broad residual savings; the compressed residual matrix is one clip and codec/pixel-format dependent; scene labels and tennis data selection are heuristics without audit-grade labels; and the SPADE/Pix2Pix code does not supply a held-out whole-codec trial. None of these older commits should be used to imply the later August deliverable and measurement contracts were already in force.

## Stage boundaries

1. **April object-stream prototype:** references, object/ball state, masks, background, and a signed lossy residual are wired through a disk-oriented demo. Mock tests and implementation only.
2. **May controls:** residual modes, keyframe cadence, temporal alignment, adaptive background detail, and early metric scripts appear. Important for the design space; no qualified end-to-end comparison.
3. **June tennis/model branch:** structured configuration, pose/control backends, dataset scene/actor extraction, racket heuristics, Pix2Pix and SPADE training. This is a real code branch, but no held-out model/corpus validation is in the source evidence.
4. **July correction and diagnostic branch:** residual-vs-encoded-source symmetry, conventional anchors, per-video HNeRV controls, source-frame offset fixes, and Phase 0 evaluation currency repairs. The clearest old result is a negative one-clip residual overhead; the broader ranking path still had a padded-black crop defect and mismatched model protocols.
5. **Aug 20 boundary:** explicit payload/reconstruction/metric contracts and subsequent metric repairs are covered in the separate August record. They should not be projected backward onto April–July measurements.
