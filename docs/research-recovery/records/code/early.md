# Early code lineage and PRs 1–72

## Scope and method

This record covers the code ancestry from the initial repository state on 25 November 2024 through the 25 March 2026 base of PR #11, then gives a change-based review of PRs #1–#72. The immutable source is `/private/tmp/pointstream-recovery-20260930/source/code.git`, with PR metadata from `github-prs.json`, the 1,165-commit inventory from `all-code-commits.json`, and archived comment snapshots. The complete machine-readable PR inventory is [early-pr-dispositions.json](early-pr-dispositions.json); it stores each PR’s full head/base/merge SHAs, merge base, exact merge-base-to-head file delta and shortstat, commit list, disposition, evidence boundary, and captured review notes.

I compared `refs/heads/pr/N` against the API metadata head SHA for every N=1…72: all 72 refs exist and match exactly. PR changes are measured as `git diff --find-renames $(git merge-base BASE HEAD) HEAD` (GitHub’s three-dot comparison). Several stale PR branches diverge from their API base; using `BASE..HEAD` would attribute unrelated changes. The affected PRs in this range are #3, #4, #5, #8, #9, #29, #43, and #66. All 72 are closed; #5 alone has no merge timestamp or merge SHA. Its head is the base of merged #6, so its work is in later ancestry even though #5 itself was not merged. PRs #49 and #50 share a merge SHA but retain separate branch deltas.

The archive has metadata for 149 PRs and 1,165 commits, but the union of merge-base-to-head commit ranges for the 149 PRs is 495 unique commits. PR membership therefore does not cover the full code history. This report handles the early ancestry directly rather than treating commits outside PR ranges as irrelevant. Review-comment completeness is weaker: the supplied inline-comment capture contains 19 comments across PRs #11, #12, #14, #18, and #45; issue-comment captures are available for #12 and #34 only. These captures do not establish that all GitHub conversations or reviews were archived. The API coverage record reports two PR metadata pages (149 PRs) and nine branch refs; tag collection was rejected by the approved-URL allowlist.

## Pre-PR ancestry: prototype changes and evidence boundaries

Initial commit `802d75ec3c594e79cd8ec1538b85e1f83abc2ec8` (2024-11-25) contains repository metadata, license, and a two-line README, not a codec. There are 179 commits after that root through `521a3ba8b3424b4572cdfc51c12a4310d3779efa` (2026-03-25, also the old-branch archive point used as PR #11’s base). This is a long-running exploratory ancestry with substantial architecture churn; commit titles and README aspirations should not be read as completed experiments.

### December 2024–April 2025: image translation, then a tennis demo

`6650e4db59a1f7bab613372e5c9bf63de228d1d6` (2024-12-03; 10 files, +620) adds a TensorFlow pix2pix/U-Net image demo in `pointstream.py`. It pairs two halves of input images, resizes to 256×256, and hardcodes a local player-video dataset path. It is not a video codec, has no scene/track transport representation, and does not compare against a conventional codec. `d50200471d335a5896394cb1837d657098a6530a` moves this code under a legacy layout and starts a scene-splitting revision. `b1f5702403aa3ce482a98f2d6c6dede6db1ac655` explicitly says instance segmentation and pose were added but not tested; later fixes do not turn that commit into validation.

The February tennis UI/server work shifts to foreground removal and inpainting. `9b9013baea6f4e0e74ef4ba7dc61d9288f2397f9` adds a basic client interface requesting local-server inpainting; `db11965efd14f54ea6f29b1f5e5bb28693d50b97` adds object detection, and `935f379585cab83e45de1f5131cf87adfba3e921` reworks it for tennis. `317201428453419aae50270c7ec49497919e0faf` adds background stitching; `3df5f608a81d6c27a072379bd66a25f25bf9e333` removes pose estimation; `a16e8c3c0c0caac9a9774ac28990d23a8c81a29f` fuses racket/player boxes; and `c0bdda4a5b2478ef3bf1666c91b707db08788863` adds segmentation, racket separation, and stitching recovery. These are successive demo-path pivots, not a stable sender/receiver protocol or an evaluated model lineage.

`16f61ba89dd5676e571fdc57731ce4c18fd4b92c` (March) consolidates behavior in monolithic `pointstream.py`; `a4b628ae52930a27346e2b76163a13938613ac5d` adds keypoint extraction. `ab874bb8515807b69bddbd8384c57cd3de1022f4` (April) adds `compute_lpips.py`, which scores paired generated/source frames with AlexNet LPIPS and resizes generated frames to match source dimensions. The script uses hardcoded paths and does not establish exact temporal identity, a transmitted bitrate axis, or whole-frame codec quality.

### July–September 2025: typed pipeline scaffold, failed runner record, and repeated resets

`dadfd6dc58483a561b7a2fa129e199609e6013d7` (2025-07-09) introduces `pointstream/core/{representation,scene,tracker}` and a pipeline layout. The server buffers scenes and uses optical-flow classification, but `process_scene` classifies and clears frames; its comment says full-resolution background generation would happen there if needed. The simple tracker is IoU/Hungarian matching with stale-active-track behavior. This is a scaffold, not encoded scene output.

`1febcfe91fe3657b4631f2ddc7cf1b53f3330349` (2025-07-31) explicitly says it uses placeholders pending student training and adds dataset/training scripts without checked-in trained weights or a substantiated training result. `e2cc2c8558f15b34cbbb46f13f9bd87d749b6adb` (Aug 4) adds a toy reconstruction: JSON background plus one appearance crop per track, affine placement from keypoint extrema, and a nonblack-pixel mask. It does not use a trained generator, coded transport, or a full-frame identity check.

`c3b34644be197df126fc10f7fb8862b592542bc9` (Aug 6, 45 files, about +5.5k lines) is a notable modular runner expansion. Its tracked `pipeline_execution_report.json` is direct negative evidence: the server exits 2 because required `--input-video` is missing; the client exits 2 because `--input-json` is missing; evaluation reports no reconstructed-video directories; `steps_completed` is empty. It records no successful end-to-end run. `16fdf5aff62a2674a63f1b1af3591e1ea4b46350` (Aug 10) adds adaptive tracking/ProPainter and documentation claims about generated outputs, but `test_enhanced_improvements.py` creates synthetic frames and attempts to read a hardcoded, untracked `artifacts/pipeline_output/test-sample0_final_results.json`. The tracked `pointstream_metrics_cache.json` mixes generic `test_content_*`, `general_tracking`, and `sports_tracking` records without source checksums, split identity, or a run manifest. Its scores cannot be assigned to a reproducible codec test set from the archive.

`cf2aa08af433e261de79af07d4c887fecea722e4` (Aug 11) deletes roughly 13,382 lines/100 files of the modular pipeline and replaces the main direction with an AV1 scene splitter/config. The next commits reintroduce segmentation/inpainting (`ccb594bccfecde35f8aef5ea93038f9caaa2c0d5`), add recursive stitching (`85749890228aa52769443d05907cfe5ea893c446`, `ceaa4fef692e10ff0d64ddd3bef4d57ae8ea7a5b`), then remove ProPainter/prompt/inpainter paths again (`c17acf4fcc1821c468d622c19c6b4839c2a284fa`). This path churn matters: README claims attached to one of these transient implementations do not by themselves identify which executable or artifacts were tested.

Late August commits add a semantic server and duplicate filter (`682239e55ac31ebd1c7accda1a33a2a1ea3a9bc2`) and a large client CGAN stack. The client’s commit `8454edac3c47da475f77848406e6243094f04739` labels itself “client side (untested).” `a4b1c1dc15cab3d88b23119693eda85521887d1d` (Aug 26) improves metadata mux/demux and background handling. September adds background diffusion, appearance-vector extraction, revised animal pose channels, and training-data caching (`ca9e685c2d81abdd55d0d1beadde7bee0172d6b4`, `b8ca72e73f3d9b29b42017fe936c3b49aa5a96f0`, `2fd9dbc6eb0e82b2a89344c440092a222322e31f`, `1e99b0ddd03c0cd3ef483b9b853348d16f74d182`). These are real model/data implementation steps, but they do not include a complete bitstream ledger or identified source/result set.

### December 2025–March 2026: codec anchors, panorama, generative client, and a separate background experiment

`25e780688aac530e9bddd8a5b7e5e0708dba0734` (Dec 17) is a major reset: it deletes around 12,990 lines of the server/client model stack and replaces them with a stand-alone anchor script. The script hardcodes DAVIS `bear.mp4`, a 640×360 setting and 20-frame cap, then gathers H.264/H.265/SVT-AV1 CRF points and VMAF after scaling to 1080p. Despite the helper name `compute_bdrates`, it returns VMAF/byte points rather than fitting BD-rate; the script has no PointStream arm and no checked-in result manifest. It is a codec-baseline exploration, not PointStream evidence.

`aabe87cfc995676d842f1a501b902f2c7deb9579` (Jan 12) adds `video_panorama.py`: ORB homographies across every second frame in its example, a still panorama, and a nonblack-pixel overlay. Failed registration falls back to identity; output is a still-image composition rather than a temporally aligned reconstructed video. The evaluator from this lineage does not match skipped-frame timing and uses whole-frame gray SSIM, and the path has neither mask removal/inpainting nor coded-rate accounting.

`efdb46cb24633c374bb7bd71356ad419925ae89c` (Jan 27, TurboNext) adds dataset/model/training scripts. Dataset code matches filenames, takes the first reference, resizes to 512×512 and samples frame-wise without a train/validation split. The model initializes SD1.5; the training script’s main optimizer targets `pose_guider`, while the visible temporal-model path is incomplete/standard-UNet based despite MotionAdapter imports. No training corpus, checkpoint, or successful training/evaluation artifact is committed with this lineage.

`780679509fac954e4a894b76edbd30a19b55fe33` (Feb 10) adds tennis data preparation: SAM3 masks/crops, H.265 CRF15 crop-video transcodes, then an external Moore AnimateAnyone `vid2pose.py` step and a `meta.json` path map. It hardcodes `/home/itec`, selects the newest `_sam_seg` by modification time, and records no portable provenance/split or full coded payload accounting. `1bae9aa177d8625cdd30d468560eea29854cd12b` (Feb 12) rewrites server/client around SAM3 tracked masks, DWPose keypoints, reference PNGs and external pretrained AnimateAnyone. Its client calls `os.chdir` into that external checkout. This metadata/file workflow is not a counted codec bitstream or a full-frame equivalence test.

`c5f744811e8f4a6aed62249a36bc76fdab69b6f3` adds `evaluate_experiments.py`. Its `_compute_psnr_for_player` scores the generated third panel against a player ROI crop, resizing GT to predicted dimensions, then aggregates per-player PSNR. That can describe a crop-level comparison, but it cannot support whole-frame reconstruction quality or a rate-quality curve; portable inputs/checkpoints and exact run protocol are not recorded with the evaluator.

Finally, `521a3ba8b3424b4572cdfc51c12a4310d3779efa` (Mar 25) adds the 806-line `background_experiment_semantic.py`, the last major old-branch experiment before PR #11. It uses SAM3 semantic prompts for tennis players/persons, tracking, ORB homographies to build an object-removed panorama, static-person reinsertion, AV1 background encoding, and full-frame/object-masked PSNR calculations. This commit demonstrates a concrete experimental direction and executable code. It contains no checked-in run output/provenance that establishes a paper result, and PR #11 deletes this script while replacing the old prototype architecture.

## PR #1–#72: what the landed deltas establish

The inventory JSON is the exhaustive per-PR register; each entry has its own exact diff paths and a change-based disposition. The early PR sequence (#1–#10, August 2025) refines the old client/server prototype: mux/demux metadata handling (#1), reference-training orchestration (#2 and #6; #5 is closed unmerged but is an ancestor of #6), video-property metadata (#3), configuration comments (#4), duplicate-section cleanup (#7), source FPS/resolution preservation (#8), segmentation parameterization (#9), and homography smoothing (#10). These are code-path changes, not evaluated bitrate or fidelity results.

PR #11 (`5745f36c2b160016d0ec5dca92194c922f10151b`, merged as `32c4c1cc278fa7eaceae99e1fbdd6ede4cd5f949`) is the architectural boundary: 42 commits and a 110-path merge-base delta (+18,156/−4,398). It adds `src/encoder`, `src/decoder`, `src/shared`, `src/transport`, the main CLI, container/CI setup, tests, tracked actor/reference-crop extraction, residual calculation, and a GenAI compositor; it deletes the older monolithic server/client, DWPose utilities, evaluation scripts and semantic background experiment. It establishes a new testable architecture, not end-to-end codec results. Six captured inline comments flag full-video frame materialization, undrained FFmpeg stderr, duplicate decode risk from missing DAG context, an always-raising dead helper, test pool cleanup, and inconsistent AnimateAnyone default height. These are actionable review notes, not verified run failures.

PR #12 (`089a00eaa051e8e00bef286cf7bdbb35a01ef192`) is a backup/main snapshot with `old/` archive, CI/dependencies and additional mock-pipeline tests. Its captured thread has seven comments: five code observations (whole-video list, process-global cwd/env/RNG mutation, GenAI-disabled path still applying a baseline, mask fill typing), a request to resolve merge conflicts, and a Copilot overview that says its full agentic suite did not run. PR #13 updates residual-delta composition and pose-window padding. PR #14 (`8b32d66c9fc1e95b83a3964139969bd4a8bdf4fc`) is a substantive evaluation correction: decoder-factory/native-size evaluation, paired tennis data repair, and report-backed claims of substantial ranking changes (ControlNet PSNR 9.76→16.06, Pix2Pix 22.98→15.39) plus 33% wrong pairings and 23% missing pairs in the prior paired data. Therefore earlier model ranks do not survive the corrected evaluator/data path. This is a model-evaluation correction; it is not a PointStream-vs-codec rate comparison. Two captured inline comments identify duplicate missing-file checks and a dataset search glob that could treat sidecars as tracks.

PRs #15–#21 are repository setup, hook centralization, a decoder helper restoration, BP21 curve instrumentation, legacy-code culling, a training stop-rule, and lint cleanup. PR #18’s body says a host encode was still running; its three inline review comments call out empty overlapping-quality intervals, duplicate QPs after VVC remapping, and incomplete cache-record handling. They concern instrumentation correctness; no result should be inferred from the PR. PR #22 (`2d6f0733c691cd7e1046dfe3884aebf3d5b5f7f1`) records an 8-frame, 4K, two-track identity-roundtrip diagnostic, while explicitly distinguishing raw residual/pixel payload from coded bits. It tests pipeline symmetry, not compression or BD-rate. PR #24 pins metric bounds/scale behavior. PR #27’s bounded IP-Adapter rescore says epoch 1 beat stock and shuffled reference but still lost to paste; re-identification adds only about 10% span. PR #29 adds a real coded plate/residual rate axis and a refusing ledger on an easy static example, but says the ladder did not run.

The first relevant end-to-end negative is PR #31 (`fa2b2ccf8093726b85f6e828b02eefa19dc3acb7`): one easiest cached tennis scene with generation disabled. Its report gives +116.8% rate over AV1 across the overlapping 39.45–44.02 dB interval and +161.5% for the coarseness curve; curves on dynamic clips do not overlap, so no BD-rate is reported. Best PointStream PSNR (~31 dB) is below the worst AV1 (~38 dB) in that run. The report also corrects a measurement path that inserted an x264 pass and changed delivered pixels. It is a scoped negative, not a universal impossibility result. PR #32 (`7f4e53e807627032c8ee93948f36d004d14cd0f2`) explicitly retracts the separate claim that same-match scenes cannot share backgrounds; pixel-subtraction failure did not rule out predictive P-frame reuse.

PR #34 is a plate-codec sweep/report only; the archived discussion says automated review hit quota, then the author reports local and CI mypy plus import-direction checks passed. PR #37 reports no low-rate crossover on one easiest 8-frame clip under its tested points and identifies an anchor metric ceiling; its own boundary forbids generalization. PR #38 wires a previously uncalled `build_plate` path and repairs registration/canvas bounds; report points are single operating points, not BD-rate. PR #39 introduces background P-frame streaming and initially prefers the first reference, but that preference was later withdrawn after a five-video analysis favored the last reference. PR #41 wires cross-scene streaming, while PR #45 records that a multi-scene run had not previously completed.

PR #45 (`b07cadb2fb1be56cd0ff477e69ed1ec2a4622b1c`) reports a bounded BP31 multi-scene comparison: 19 BD-rate points favor the N=2 stream over AV1, yet overall PointStream still costs +90.97% vs AV1; wall time is about 20× and the plate-codec JPEG reduction of 3.6–4.1× is about 1.45× at the ladder’s operating points. The findings are scoped to the sampled tennis sources and tested operating points. The same change corrects a background-share bound that falsely alarmed despite a working stream. Three captured inline comments note that bound error, an import-layer regression risk, and a test that did not actually execute the failing runner path.

PR #48 (`f7619284e8081fd2ba55cda606b3e9ca75d5f46a`) is an explicit circularity retraction: the claimed client-side plate/residual representation used a residual derived from the source at decode, so it was not independently transmitted. The remaining plate hypothesis still requires full accounting and held-out confirmation. PR #50 implements a canonical canvas diagnostic, but padding-byte changes are not evidence of transmitted savings and later work corrects the panning/warp-back issue. PRs #51–#56 add low-rate floors/axis types, integrate the experiment plumbing, identity-safe recovery, archive reports, resume neighboring QPs, and document contamination controls. They improve protocol/instrumentation; they do not independently confirm the system.

PR #57 (`6a4b06917858d8cb6647c914c300cbb0e28a1b14`) audits 37 scenes/five candidate videos and records no confirmation videos and zero accepted confirmations (0/6). PR #58 is a bounded background CRF search (3/3 PointStream submissions and 8/8 references succeeded), not a full coded-system comparison. PR #60 creates a source shortlist without downloading or activating candidates. PR #61 is a three-point background scaling diagnostic: CRF51 matches BP52 quality with +56 bytes metadata; half scale saves background bytes but harms quality and does not beat cited AV1/VVC diagnostics. PR #63’s two acquired clips are explicitly ineligible for confirmation. PR #64 finds higher effort at the same CRF spends more bits while AV1/VVC references remain unranked.

PR #65 builds Gate A infrastructure. PR #66 fixes its contracts and states no native-4K curve point had been launched. PR #69 (`22922136944f9d0ef4331cadb5e1357ad24150a5`) then reports an actual native 48-frame negative: PointStream loses against SVT-AV1 preset 0 and the slower VVC reference in the tested condition. The background-only CRF63 stream is 348.5 KB, 3.19× the entire 96-frame AV1 QP63 stream (109.2 KB). A longer 96-frame run was projected to exceed 55 minutes in a non-resumable subprocess; the salient-object alternative is a proposed pivot, not a demonstrated result. PRs #70–#72 are revised competitive-regime plans; projected VVC background/crossover rates and amortization remain hypotheses, with PR #72 explicitly prioritizing empirical checks such as avoiding PNG I/O and profiling the client.

PRs not expanded above are still analyzed individually in the JSON inventory. Those are marked with reason and boundary per PR rather than treated as duplicate results.
