## Four additional DiffuEraser scripts

`smoke_fill_budget.py` compares a 24-frame processing budget distributed across source durations/cadences and sizes. `smoke_fill_scale.py` varies maximum image size on a retained press second. `smoke_fill_grid.py` crosses resolution/cadence with continuous versus joined source seconds. `smoke_fill_temporal.py` joins four press seconds and samples lower cadences. Sources point to factory001 press data and external `pointstream-data/jobs/neural-bg/{budget,scale,grid,temporal}-smokes/report.json`; the experiment audit owns saved-report interpretation. None was executed by this recovery.

Their score target is a **saved generated DiffuEraser fill**, not independently observed unoccluded background. Inside/outside-mask MAE against that fill is a consistency/approximation diagnostic. The sampled frames are written at 30 fps, so source sampling cadence differs from encoded playback duration. Joined seconds are not a continuous source interval. Maximum image size should retain its exact parameter name until actual output dimensions are verified; “360p/540p/1080p” prose alone is insufficient.

Result reuse checks only existing paths/nonempty files, or case names in a saved report, without input/configuration hashes. Zip/min-length scoring can omit unmatched frames; recorded requested frame count alone does not prove every output was scored. Recorded wall time includes conditional cache reuse and extraction, so it is not automatically a comparable inference-time measurement. No code/patch, checkpoint, GPU, environment or native-tool version packet is emitted by these scripts themselves. Surrounding manifests may recover those fields; otherwise they remain missing.

Paper use: retain the resolution/temporal-budget question, generated-target dependence, noncontiguous-context boundary and cache/provenance lessons. Do not promote missing reports or low MAE against a generated reference to background fidelity, a neural-codec rate advantage or a held-out result. A valid next comparison freezes decoded input indices, all output counts, model/guidance and dimensions, scores with an independently declared target, and records whether timing includes cold inference or cache reuse.
