## High-priority provenance finding: the published demo's clip IDs do not resolve to one clip set

The committed demo artifacts contain incompatible source identities under the same `clip_01` label:

- `source/live-demo/demo/outputs/results/comparison_results.json` is timestamped `2026-09-16 14:50:20`, names three clips `clip_01_factory001_worker001_00001`, `clip_02_factory001_worker001_00002`, and `clip_03_factory001_worker001_00000`, and gives each 300 frames / 10 s. It records Ada hardware and session-level results but no input SHA, exact code revision, encoder/judge checkpoint identity, or source-manifest digest.
- `source/live-demo/demo/outputs/results/rtm_encoder_report.json` also names those three `factory001_worker001` clips.
- `source/live-demo/demo/outputs/results/demo_streams.json` instead maps `clip_01` to `/home/itec/emanuele/Datasets/Egocentric-10K/curated/clip_01_factory035_close_hands.mp4`, and maps clips 2–3 to `clip_02_factory001_starve_win.mp4` and `clip_03_factory001_high_det.mp4`. Thus even this three-clip manifest mixes a `factory035` clip and `factory001` clips; those names do not match the earlier benchmark records.
- The archived hand-model JSON reports (`outputs/hand_model_compare/{rtm_scales,vitpose_densepose}/report.json`) also use `clip_01_factory035_close_hands.mp4`, for eight sampled frames. They are not measurements on the old factory001 website clip 1.

Recovered-only commit `912b0d7f288b1086039b39538b4e67db797eb3d9` is the explicit correction alarm: “the generator and website rungs were built from the old factory001 demo videos, which may not be the newer dataset.” It changes `interactive_demo.html` to mark the `rtmsam1` asset family and says the source clips may be wrong; it nulls PointStream task values only for clip 1, while clips 2–3 still have numeric task fields. The commit adds `--mask-dir` for per-clip SAM files, but a missing per-clip file silently becomes `None` and processing continues without that SAM alpha. Its dataset code labels the wrist-x hand-side heuristic and old-factory generator as “AT RISK.” No input hashes or replacement manifest are added. This proves unresolved identity and a concrete cross-artifact contradiction, **not** which clip was intended or that a replacement ladder is valid. Preserve the status as unresolved/quarantined pending a hashed clip-to-stream-to-report reconciliation. The 912 object is retained-only/private (branch `refs/heads/mac/cursor/rtm-sam-ladder-at-risk`); it is not a public main correction.

### RTMPose hand model comparison and live encoder switch

**`5add7f7a8b9f8b0047f3c68f1c88493b2530903b` (2026-09-28)** compares hand models “as encoders and as judges” on eight sampled frames. Its archived output JSON says the source is `clip_01_factory035_close_hands.mp4`. The `rtm_scales` report gives every compared model exactly 23.28 kbps / 97-byte mean packets because the fixed 21-point packet format—not the models' actual recovery advantage—determines that payload size. The report uses pairwise model-agreement judges; self-comparisons are perfect by construction and other scores depend on the reference detector. The Hand5 RTMPose-m is not the same task/model as a whole-body estimator. ### SAM 3.1 and the live demo's mask oracle

**`ab9339d727dc4c1e133906ef5ac8e3dacc23d594` (PR #145, 2026-09-27)** lands local SAM 3.1 integration, observation/perception adapters, DWPose, and runner wiring. The later code dossier already describes the implementation boundary. Selected retained SAM records offer useful narrow evidence, but the records are tennis: the 16-frame prompts use `sinner_alcaraz/scene_002`, 3840×2160 frames, `sam3.1_multiplex.pt` SHA256 `0567debe…3541cb6`, and pinned SAM source commit `2345a4ad…dc08c40`. The “tennis player” smoke is inference-only and compares against project-derived imperfect cached masks (mean IoU ≈0.803, boundary IoU ≈0.059); the “tennis racket” prompt has 0.75 two-track coverage and no independent racket annotations. Both report no PointStream codec run and explicitly say masks were not yet sent through a source-hidden serializer/decoder. These are tennis mask diagnostics, not egocentric hand-mask or task-metric validation. A separate three-scene tennis pilot retained on GPU5 later found unresolved racket-mask failures; the training manifest stayed inactive and the external visual review overlay was not applied. See `workers/server/outputs/selected_reports/journal-20260925/`, `journal-20260926/`, and `sam31-unification/` for run manifests/results.

**`b95173c113ae52c26dc33e041b604ac7aec2f28d` (2026-09-29; PR #149 content)** adds `compare_mask_oracles.py`. Despite “rate” rows, this is an oracle splice: for each candidate support, the program copies exact source/reference pixels inside the mask and uses an encoded background outside; the rate adds a mask/pose payload plus background, but does not transmit or charge the copied foreground RGB. It is therefore a privileged upper-bound diagnostic, not a reconstructible video arm. RTMPose both defines support and judges pose (declared partly circular); YOLOE may similarly define and judge segmentation. DINOv3 is assigned the AV1 CRF-63 240p PCA preview rate rather than its feature payload. The default screen uses a 48-frame prefix, hard-coded published clip rates, and nearest-rate AV1 rows; these choices must remain explicit. There is also a code/report mismatch: the module docstring says YOLOE is marked partly circular when it is also the segmenter, but `load_candidate_supports()` supplies `False` for the stored `circular_segmentation` flag for every candidate, so the output does not encode that dependence. No `compare_mask_oracles` result JSON appears in the committed `source/live-demo/demo/outputs` or searched selected reports. More specifically, the retained maps tree has Canny, DINO, DW-Pose and YOLOE payloads but no native `sam31_masks` / `sam31` payload; the runner would emit `error: no native SAM payload on disk` for that candidate rather than a SAM score. Thus PR code/test presence and its body do not establish a completed four-map result.

### DiffuEraser and archived neural still fillers

It writes a contact sheet and a small `smoke.json` containing notes/frame count/sheet/device; it does not score temporal consistency, foreground/task metrics, rate, timing, or a transport/decode path, and does not record the input, mask, model/checkpoint or software hashes. The `holdout_windows()` helper describes a middle 10 s split with 2 s gaps, but this smoke runner does not train on that split or score its hold-out. No matching `smoke.json`, contact sheet, or DiffuEraser result was found in retained code/results. Status: **prototype code / smoke intent; no audited visual-run artifact or measured background/codec result**. SDXL, FLUX and Qwen still-image approaches remain archived; their archival is a scope decision, not a comparative rejection.

### Neural video benchmark / cross-domain boundary

The relevant code-path work does not fill the gap. PR #122 (`b378d7214c6e47cf31d66f59ab6420fca8e00a38`) reserves neural-anchor compatibility and source records; PR #142 (`1caa01a1e07455238d45f4927b5e579426ad0f28`, integration `97a85b99054733be78d0c4055c19e0357acf301c`) adds a harness/spec for a six-source neural benchmark, not six scored independent videos. Its `rate_ladder.py` preserves table constants and supplied weights; it does not turn those into measured per-video encodes. PR #130 (`2ca810338e6ecf41156f65baa350fa4deb4bbdd8`) explicitly records no neural video benchmark and no confirmation scoring. Do not treat neural anchor planning, benchmark schemas, demo generators, or DiffuEraser visual inpainting as one another's task-rate evidence.

Likewise, tennis foreground work in PR #143 (`4815aa07e4491307d44fbf7e1500ffbf0cc60c41`) has its own 48-frame clips, source exposures and cap; its reported no-qualifying-point finding cannot validate or falsify the egocentric hand demo. SAM/mask code can share interfaces and failure lessons, but clip IDs, masks, payloads, checkpoints, input splits, output/task metrics and charging stay domain-specific.

## Audit disposition

There is real demo engineering and several bounded observations: a three-clip factory001 starved-ladder record; an eight-frame factory035 hand-model screen; a synthetic border-strip rule test; tennis-only SAM model outputs; and code for privileged-mask and neural-fill diagnostics. These support implementation and clip-specific demo decisions. Source identity, encoder/renderer alignment, detector/judge circularity, uncharged copied pixels, missing egocentric SAM payloads and absent neural smoke artifacts prevent treating them as a single current egocentric benchmark, a verified “RTMPose+SAM” rate/task ladder, or TOMM codec evidence. The wrong-clip question remains unresolved pending exact input hashes and a per-clip rebuilt record.
