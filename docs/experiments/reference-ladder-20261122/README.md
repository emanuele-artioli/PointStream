# Shared reference settings at three image budgets

The reference-ladder figure asks which codec and shared integer quality setting preserves the two development reference images under 25,000, 45,000 or 65,000 total image bytes. The previous three samples per codec unevenly covered these budgets. These caps span the previously measured low, middle and high AVIF payloads. Select solely on size within each codec before comparing quality. The hypothesis is that JPEG, WebP and AVIF trade places or reach different fidelity at these budgets. A competing outcome is that the earlier apparent advantage largely came from unequal operating points.

Use the same two authenticated 512×784 source RGB images. For each codec use a bounded size-only bisection, retaining the highest **tested** setting whose combined actual image bytes fit. Both players share that setting. Use the same encoder and decoder implementation throughout each codec, verify round trips, report both individual RGB PSNRs and the actual unpadded bytes. Primary development comparison is the lower of the two players' PSNRs at each cap. Image payloads exclude transport and adaptation. Note gaps to the next tested setting. Reuse measurements from the common-reference study for verification rather than treating each codec's numerical quality scale as interchangeable.

Smoke on the actual two input images at Q65 per codec, pin native tool hashes and confirm the archived WebP and AVIF output hashes at that setting. Up to 180 local CPU-seconds, five wall minutes and zero GPU for the size search. No threshold, budgets or candidate codec changes after scoring. A production ladder needs a blinded generated-motion comparison and validation on other players, including whole packet bytes and refresh cadence.

All three codecs reached all three budgets. AVIF led both references at every cap. For the lower-scoring player at each cap, JPEG achieved 33.90, 38.63 and 40.97 dB, WebP achieved 38.39, 41.04 and 43.33 dB, and AVIF achieved 39.15, 42.01 and 43.92 dB. These are still-image fidelity results on two development images.
