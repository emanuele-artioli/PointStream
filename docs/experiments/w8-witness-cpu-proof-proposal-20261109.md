# W8 exact-source CPU proof proposal — not released

Purpose: qualify the new W8 witness source, strict worker policy and process teardown before any new GPU request. This is synthetic infrastructure and packet/native correctness evidence, not generation, kernel, quality or full-witness evidence. No execution, upload or release is authorized by this proposal. Root must review the complete frozen entrypoint, fleet spec, source and cost model before any submission.

## Bound and admission

Reserve at most **800 CPU-s and 0 GPU-s**, wholly inside the existing 4,550 CPU-s W8 phase: at most 50 CPU-s shared fresh readiness/source preparation, at most 600 CPU-s for the one-core fleet campaign, at most 100 CPU-s for supervisor/claim release and publication-to-canonical-terminal completion after the campaign, and at most 50 CPU-s independent audit/closeout. These are distinct caps, not measured usage. The campaign must inherit a verified single CPU affinity throughout the owned tree, enforce a hard deadline (at most 45 minutes from release), hard wall and per-process CPU limits, capture waited child CPU and process identities, and stop before a stage whose upper bound cannot fit. Charge the conservative whole one-core lifecycle wall plus separately bounded preparation/audit; pending wall time is not CPU time, but queue-watch and administration CPU remain in the external allowances; do not claim aggregate CPU was measured from one parent counter. Preserve all partial artifacts, and inspect an uncertain submission rather than replaying it.

The prospective smoke allocation is 130 seconds packet + 90 seconds synthetic namespace + 120 seconds MAIN/JCV policy + 135 seconds for three native invocations + 50 seconds setup, publication and cleanup = 525 seconds, leaving only 5 seconds within the 530-second smoke. Each native allowance includes its 20-second command bound and 25-second outer reserve; the campaign separately reserves 50 seconds validator, 5 seconds completion marker and 15 seconds slack. These are caps, not measured times, and any admission/remaining-time failure stops. The 100-second post-campaign allowance includes the observed prior approximately 60-second interval with a 1.5× margin (approximately 90 seconds), not an assertion that this source will match it.

Prior evidence informs feasibility but is not a guarantee: packet job `20261105T051531Z-bd0b5915` had a packet worker at 6.426 CPU-s/6.531 wall-s, though its original fleet validator failed and only independent artifact audit accepted the substantive checks. The earlier native inventory v4 completed in 9.9435 wall-s and its independent audit rehashed the pinned 47,001,600-byte YUV, but it did not establish restricted execution or this new source. Cold filesystem, source staging, fresh protected SHA reads, native repetitions and strict policy proof may dominate. Measure or conservatively cap them; if the actual combined forecast does not fit the 600-second campaign and its 530-second smoke, stop and obtain a revised prospective reservation rather than shrinking scientific or cleanup checks.

Expected source is the final coherent source, not the earlier source for which tests or proofs passed. Do not request a GPU or share an active CPU claim.

The staged/input map must include the exact accepted public packet/profile and W6 guider, independent 480-tensor oracle, base/AA assets and authenticated current preflight/identity records required by the unchanged strict packet setup; MAIN/JCV packed runtime identities; fixed native inventory `cd6bb8cf2a239d94f595fd92f823cf6406c018e1fbda745e81cd0c0e91d1b59b`, pinned FFmpeg/loader/library identities; approved clock-helper/leaf profile and protected-file expected identities. Inputs must be SHA-identified, read-only and sourced through registered fleet staging; fresh outputs and control receipts belong to a new scratch/result directory. Record every actual path and digest in the final reviewed spec; this proposal does not invent source or environment digests.

## Required actual checks

1. Exercise the exact production reaper with its fixed CPU-only synthetic harness: normal, timeout, TERM and KILL; in every case observe and retain host PID, start ticks, process group and PID namespace identity for namespace init and worker, plus the synthetic detached child, and verify their disappearance. Normal exit must record init and waited child CPU and agree with independently waited outer-child CPU within the declared 0.25-second synthetic-workload tolerance. Timeout/TERM/KILL must retain cause and any pre-exit identity receipt. The kernel PID-namespace teardown supports the bounded descendant containment claim; do not claim an individually observed inventory of unknown descendants.
2. Run the exact fixed native CPU target under that same reaper: one normal real FFmpeg/libdav1d invocation with the pinned IVF, exact binary/loader/library inventory and expected YUV SHA `7490edf9b678db805c23baae49a2a3b5e9d7b037b18dd216320aad47a061beff`, plus separate bounded timeout and SIGKILL cases. Record trusted init/bootstrap host PID/startticks/namespace and verify their post-stop absence. The early namespace identity record must exist before interruption; missing or malformed identity, live owner or unverified cleanup fails the proof. Native execution may use its own session inside the PID namespace; no native GPU is allowed.
3. Run the new source's actual isolated CPU packet path with original packet and identity gates: exact decoded checkpoint and 480 individual name/shape/dtype/raw-byte fingerprints, both packet unit NPZ hashes, native packet framing, protected-file identity and 10 denial probes, seven mutation denials, exact source manifest, runtime grants and preserved canaries. Verify CUDA remains hidden and uninitialized. Verify the new mode allow/deny path and exact 12 approved system leaves plus bound clock-helper source/policy using genuine Linux namespace/Landlock calls, not a mocked policy or synthetic successful JSON. The proof must cover qualification and full-witness dispatch without generating model outputs; any policy operation requiring CUDA is instead a separately admitted GPU gate and must not be claimed as a CPU pass.
4. Independently validate and seal the exact raw receipts, source/spec/input hashes, runtime/host, stage statuses, affinity/lifetime/cost records and cleanup evidence. The current WIP `w8_witness_job.check_cpu_gate` expects schema 1, scope `root-reviewed W8 same-source CPU isolation and native lifecycle proof`, `passed: true`, `source_sha256`, `snapshot_sha256`, `revision`, `environment_sha256`, `host`, actual `job_id` and `spec_sha256`. Its `raw_receipt_sha256` must contain distinct SHA256s for `namespace_lifecycle`, `native_normal`, `native_timeout_kill`, `strict_modes` and `independent_audit`; its exact `checks` set is defined by `REQUIRED_CHECKS` in that module. These booleans are a root-reviewed attestation only after raw receipt and lifecycle audit; they are not themselves evidence. Envelope must bind all separate case and policy receipt hashes to this exact source and spec, with explicit passed/failed scope, rather than inferring one check from another. Retain failures and partial source/receipts. Release unused reservations only after root audit.
