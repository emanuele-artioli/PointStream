# Source-only racket-localization oracle

Before opening detector outputs, freeze the 16 official racket boxes already inventoried on match209 (6 boxes), match235 (4), and match269 (6). Use the authenticated 1280×720 RGB source conversions and official source boxes, scaled outwards by 2/3 using the same rule as the prior racket study. Apply pretrained Ultralytics YOLO11x COCO detector, class 38 (tennis racket), one CPU thread, fixed default confidence 0.25, NMS IoU 0.7 and 640-pixel inference. No training or tuning on these frames. One-to-one box assignment maximizes total IoU; report official-object recall at IoU ≥0.5 and the more permissive ≥0.3, by match and pooled, as well as all per-object detections. IoU 0.5 is the admission endpoint, with at least 12/16 (75%) required to motivate testing a detector-triggered crop; 0.3 is diagnostic, not a replacement pass. Boxes with no eligible prediction remain misses. COCO-to-broadcast training overlap is unknown and this small source sample is descriptive, not a population estimate.

Run a source-only three-frame CPU smoke, one fixed first labeled tick per match, check hashes, device, class, finite output and forecast full cost with 1.5× margin; if full ≤600 seconds after fixed setup, evaluate all 15 labeled ticks and 16 boxes once. This is a feasibility gate only: no generated players, racket encoding, crop payload, grip fidelity or machine performance on compressed frames is established. Raw source frames stay on campus and only non-image numeric outcomes may enter Git. Budget ≤900 single-CPU-seconds, zero GPU; no model switching based on outcomes.
