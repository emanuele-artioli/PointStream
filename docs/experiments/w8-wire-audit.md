# Experiments: W8

Entries for this item, oldest first. The protocol and entry template are in [experiments.md](../experiments.md).

### 2026-10-31 — Fresh-decoder wire audit (prospective, read-only)

- **Goal.** Determine what is actually paid and independently reconstructible for W7's saved hybrid, and identify the smallest witness needed before calling its rate a complete decoder bitstream. **Hypothesis:** the coded keypoints and references plus shared decoder models are sufficient to reconstruct the measured output with modest additional framing. **Competing explanation:** required model/tensor directories, source-derived state, identity binding or sampling state is unavailable or larger than the remaining rate margin, or a clean receiver fails to reproduce the saved composite. **Budget:** read-only source and existing-record inspection ≤120 CPU-s, zero GPU and no experiment job. No serialization or new quality claim is authorized here.
- **Accounting boundary.** The historical judge charges actual native AV1 IVF bytes, the actual KPS2 packet (including its own compressed metadata, lengths and integrity header), and a per-window JSON research bootstrap. That JSON contains window, fps, scale, 240-frame length, saved-tick convention, player unit names, deterministic seeds, decoded-base fallback and KPS/IVF hashes. It also includes modeled amortized reference-bank and adapter/guider terms. It is not a complete multiplexed, independently decoded wire format ([judge](../../experiments/tennis/k6b_real_base_judge.py), [packet codec](../../experiments/tennis/k6b_rate_streams.py)). Native IVF/KPS are actual serialized components; the research JSON is actual serialized metadata, but no end-to-end transport assembly has been verified.
- **Reference-bank assumption.** Each W7 window's generator was conditioned on its two own source-derived first-fitted-scored-frame crops. `rate_transport` serializes and round-trips a PNG `.ref` per player, including unit, reference tick and box; JPEG 70/85/95 are alternatives, not additional crops. Corrected W7 billing models a 12-crop bank by multiplying the two PNG packet sizes by six and amortizes it over 7,200 s; it is not evidence that those exact 12 crops were delivered or that a future window can reuse them without quality loss. Actual two-crop PNG packet sizes span 152,664–366,161 bytes in the nine W7 windows ([W9 correction](w9-adapter-break-even.md)). The old bank comprises crops from six different windows and has no established cross-window named-player identity mapping ([W7](w7-untouched.md)). The generator actually reads the prepared reference array; a decoder must instead bind and use the decoded `.ref` pixels and prove equivalence.
- **Geometry and identity.** KPS2 carries track names, sampled q4 coordinates, every-frame visibility, run timing, frame bitmap, compositing order and profile/crop/context/seed declarations. Existing `native_equivalence` checks recompute run boxes and pose-map pixels exactly against saved prepared arrays; the box rule uses full-run pose statistics and centered smoothing, so buffering/lookahead is required. Reference box/tick are in `.ref` metadata; verify binding to the unit and correct reference on an independent receiver. Seeds are derived from unit names and run IDs. Frame dimensions, conversion, ordering and temporal gaps/fallback must be fixed in a decoder contract; do not assume a JSON research header alone implements these. The source-derived registration bitmap and ordering are paid within KPS metadata; judge-only target masks, source RGB and fixed scoring region are **not** decoder inputs and must not leak into the witness.
- **Unproved receiver inputs.** Generation currently consumes prepared `reference`, pose, run and box arrays and writes saved generated crops; the quality judge reads those crops, separately saved predicted SAM masks, GPU-decoded base arrays and KPS-derived boxes. A private SAM worker has shown repeatable masks for saved crop inputs, initialized from decoded pose prompts, with no transmitted dynamic matte or prompt bits; this does not prove fresh end-to-end regeneration produces the same crops/masks, nor account for any correction needed if it does not. The native paid AV1 bitstream must independently reproduce the actual RGB input and rounding path. SAM model/runtime/version and sampling conventions are part of the installed decoder contract. The 80 saved W7 ticks do not demonstrate full 240-frame decoding or live latency.
- **Weights and model lineage.** The accounting grants installed generic generator/segmenter and common tennis-base weights; this is an explicit deployment assumption, not free universal content. The common `tennis-base@fit-100` is itself trained on footage from the Alcaraz and Medvedev matches plus other matches; those Tier 1 matches are familiar, whereas Tier 2's Nadal–Kyrgios generator base did not see that match (its match adapter was trained on the first half). Exact upstream/pretraining and replay independence remain scoped to recorded audits ([lineage receipts](k6b-players.md), [W7](w7-untouched.md)). Match-specific adapter and pose guider are charged over 7,200 s: the frozen Alcaraz and Medvedev measured terms are 1,488,252 and 1,495,592 bytes respectively ([rate code](../../experiments/tennis/w7_rates.py)); these are per-tensor charges, including quantization scales and LZMA framing, not complete serialized decoder payloads. They lack a serialized tensor directory and complete receiver bootstrap. Separately, the recorded common tennis-base checkpoint is 48,878,567 bytes; including it at installation or amortizing it is a sensitivity, not an added charge hidden in the primary rate. Any required generic decoder and SAM installation must be declared separately, not mislabeled as match payload.
- **Minimal next witness and units.** Freeze one window and one declared decoder profile; serialize a complete self-delimiting bundle containing IVF, KPS2, the *actual* reference packets, match adapter/guider tensors with directories, scale/shape/name and quantization metadata, model identifiers, ordering, timing and any necessary initialization/corrections. From an isolated fresh process with only that bundle and explicitly identified installed models/code, decode references/keypoints/geometry, native base, generated crops, masks and composite at the same 80 judged ticks; assert hashes or a prespecified platform-tolerant numerical/quality control against saved outputs, and audit file reads to exclude source/target/prepared/saved-result access. If it passes, repeat on 240 frames separately before a full-rate claim. Count the bundle bytes exactly once, distinguish per-frame, per-window, per-reference refresh, per-match and one-time installation costs, and recalculate the rate at the actual amortization interval. A mismatch is unresolved until corrected and its bytes paid; no numerical unmeasured overhead or complete-codec win is inferred.
- **Search limits.** This is source and checked-in-record inspection, not a fresh decoder execution or independent remeasurement of all historical byte fields. The prior receiver isolation applies to mask prediction from saved generated pixels, not an end-to-end complete bitstream. Source/quality evaluation files are distinguished from receiver inputs by their code path, not asserted absent from an untested deployment. No new files in `Datasets`/`Models` and no experiment job.
