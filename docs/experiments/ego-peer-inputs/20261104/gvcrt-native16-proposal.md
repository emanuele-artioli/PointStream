## Decision, budget and exposure

**Hypothesis:** after the CPU entropy prerequisite, the authored q3 16-frame native path can encode a complete stream and independently reproduce it from the charged manifest and declared checkpoints within a bounded GPU smoke. **Competing explanation:** this torch/CUDA/pybind configuration, isolation profile, model ABI, padding, reset path or strict source contract prevents native parity or exceeds the allowance. A failed interface, incomplete stream, no quality overlap or resource limit is *unqualified*, not a negative result for the GVC algorithm.

Proposed cap for root review only: **≤600 GPU-seconds for the single smoke** and **≤900 CPU-seconds total**, including fixed inputs, one-core preflight, encoder, fresh receiver, metric scorer, native validation, retained receipts, failed starts and monitoring. Reserve explicit lifecycle and release time within those caps; each subprocess gets its own shorter stop bound and a process-group cleanup plan. This is a ceiling, not an estimated runtime: the old contended 16-frame partial stream has no valid timing forecast, and the K5d smoke's 204.98-second six-point total is not a GVC timing estimate. If admission cannot guarantee the bounds, do not run. A numerical peer comparison may proceed only when genuine source-signal parity, source-denied decode, metric and byte ledgers all pass; any later 3-point rate curve or new source needs a separate cost pilot, preregistration and reservation.

Both GVC checkpoints are generic pretrained shared-state files; their authors' training datasets and any overlap with this TrackNet clip are **not established** by the local receipts. Do not invent clean/unseen status. The calibration labels/frames are retrospective and reused; the scorer's judge exposures must be audited as in the retained benchmark. No model is trained or adapted in this phase.
