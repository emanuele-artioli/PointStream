This is not an independent official-entrypoint round trip or an intrinsic quality ranking of GVC. No GPU, model, native re-decode, source-frame regeneration or new footage export was performed. The official source export SHA `a7ad708cfaea7d0030cc1d78bd2cd1f1d62a1df999d8eaece292bff510c30f7e`, revision `d0e32bfa3e8e282f9a77437c223c605858eea637`, contains the released `test_video_gvcrt_1088.py`, model and input-reader sources. Comparing that code to the frozen native bridge establishes:

- PNG/RGB input is CHW float in [0,1], converted to half precision, replicated to the released minimum 1920×1088 canvas, and scaled to [-1,1]. The adapter's RGB path and crop/clamp/inverse normalization match the official PNG path. The project first converts original RGB through limited-range BT.709 YUV420 and back to RGB for a matched conventional-codec input; the scorer compares to original RGB. The recorded conversion-only pooled RGB PSNR was 41.457 dB. This is an additional evaluation choice, not the official original-PNG input pipeline.
- Base I and P QPs are both 3; these are model indices, not conventional-codec QPs or a quality equivalence. The P QP follows the released index map and `qp_shift=[0,2,1]`. The registered sequence has one initial I and 15 P frames, with feature-adaptor resets on frames 1 and 9; entropy partition uses the released padded-size criterion. The official entrypoint permits other intra and reset intervals and separate I/P QPs; this result does not test those options.
- The adapter follows the released I/P compress, packet/SPS and fresh decode flow, including I initialization, P reset, decoded canvas crop and inverse scale. The official I loader permits partial state loading; the adapter applies the same I/P checkpoint-key preference and requires stricter complete state coverage, recorded for both encoder and receiver. It selects the unfused eager path; this is an implementation choice and no kernel trace or independent bitstream interoperability was produced.
- The saved receiver array independently rehashed to its recorded digest and has dtype float32, shape (16, 3, 720, 1280), 16 finite frames and global minimum 0.0 / maximum 1.0. The scoring adapter clips to [0,1], rounds to uint8 and moves CHW to HWC. RGB PSNR uses per-pixel squared error on matched source/received uint8; LPIPS scales uint8 to [-1,1], DISTS to [0,1], using the same scorer as the anchors. Official example PSNR evaluates float reconstructions before optional uint8 output, so this scorer's round-to-uint8 convention is a deliberate small difference from that example.
