# Generation and bootstrap implementation review

Review of `w8_receiver_generate.py`, `w8_receiver_bootstrap.py`, their focused tests and the called `k6b_generate.Renderer`. This is source inspection only, not host qualification or a GPU result. The source was concurrently owned by the receiver-design agent; findings were sent to that owner for correction. Line numbers reflect the inspected version.

1. **Frozen code binding is incomplete.** `w8_receiver_generate.py:169–175,215–220,239–246` compares loaded Moore-AnimateAnyone module paths and hashes with the *same worker configuration* that declares them. It does not compare `k6b_generate.py` to the fixed profile's `models.generator_code` (`00248aa4fdd47e634f82b37a7a33c99f1794440d65cbfe9395255a4225735542`), and a self-consistent edited configuration and substituted AnimateAnyone tree can pass. The recorded AA source archive is SHA256 `bfca6cf1129a0154bf2c3431c0e01b34f5e815eda5ba504f54e001c8ceeb99ee`; installed-tree correspondence is explicitly unresolved in the asset manifest. Bind actual imported module bytes to an independently reviewed source/archive manifest and fixed profile before model execution. Merely recording paths or trusting a configuration generated from the same installed tree is insufficient.
2. **Deny probes need binding to actual protected assets and aliases.** `w8_receiver_bootstrap.py:166–188` requires one nonempty list per category but accepts arbitrary distinct files as the source/prepared/fit/golden/mask examples. Its alias list may contain aliases for just one category, and path-based allow/deny comparison at `:93–100` does not detect an allowed hardlink to a protected inode. Thus a formally valid config can probe unrelated files while leaving a required real alias accessible. Bind the reviewed manifest's actual paths and `(device,inode)` identities, reject allowed files/trees exposing any protected inode, and require/probe each required real alias. Avoid broad recursive per-file scans on shared NFS; use explicit reviewed aliases and narrow grants.
3. **Kernel evidence does not exercise the declared full context.** `w8_receiver_generate.py:221` calls `Renderer.probe`; `k6b_generate.py:181–185` profiles only eight frames and one diffusion step. This does not establish the sampler's actual 24-frame, four-overlap context kernels. The card requires a representative whole-context device/kernel smoke. Profile a bounded representative 24-frame context under the real sampler and record the observed events; the full-window run itself remains separate.
4. **Qualification checks happen after full generation.** `w8_receiver_generate.py:203–221` checks only that CUDA exists before model initialization and the short probe. The class, runtime, kernel families, tensor-core evidence and CUDA placement checks in `check_execution_receipt` at `:285–303` run only during the post-render `validate_sealed` at `:339–340`. A mismatching class/runtime/probe can therefore use a whole 240-frame render before failing. Evaluate the same checks immediately after the representative probe and before the 30-step full render; the validator should repeat them independently.
5. **Launcher accounting and timeout are not whole-process guarantees.** `w8_receiver_generate.py:344–367` limits only the worker's CPU inside the bootstrap and uses `subprocess.run(..., timeout=...)` for `unshare`. It does not account for launcher/unshare CPU in a campaign receipt or explicitly terminate and reap a task-owned process group on timeout. No reviewed aggregate allocation here covers parent, namespace setup, worker and cleanup. Enforce and record the campaign-wide bound and process-group cleanup in the launcher/supervisor; never replay an uncertain termination.

The fixed packet and profile are checked in the isolated packet stage, the decoded 480-tensor fingerprints and unit NPZ identities are tied to the CPU oracle, the model uses the original zero-bit re-quantization path and 30-step/2-guidance recipe, and crop coverage requires the original 80 ticks. These checks do not resolve the five gaps above. Existing focused tests cover recipe, packet/crop tampering, select denial behavior and individual model/kernel receipts; they do not exercise actual historical source-archive binding, every protected category's aliases, full-context profiling, pre-render qualification or timeout process-group/accounting behavior.
