# W8 fleet cost probe contract — review draft

`fleet-cost-template.json` is deliberately **not dispatchable**: root must replace the preflight-bundle and identity receipt paths/hashes, original independent oracle report path, deadline and any resource ceilings after actual CPU qualification and a fresh fleet/host admission. Freeze the physical source snapshot, normalized spec and immutable input identities. The profile, packet, original 8047… oracle report, common-base archive, AA archive, eight weights and two independently identified preflight artifacts are staged as exact SHA-256 inputs. The preflight asset receipt contains original protected file path/hash/device/inode identities and AA/SAM source checks. Protected files themselves are not staged into the receiver; aliases are made host-locally and only probed after isolation.

The preflight bundle is a root-reviewed JSON object, itself staged with an explicit SHA in both `--preflight-sha256` and the fleet spec. It contains `passed: true`, `identity_sha256`, `source_tree` (the absolute path used by the preflight), `frozen_source_files` (relative preflight source paths to their SHA-256), `result` (the exact CPU-preflight `result.json`), `receipts` (the parsed MAIN and JCV `preflight.json` files), and `runtimes` with MAIN/JCV `python` and explicit reviewed `allow_paths`. The embedded preflight receipts are rehashed against `result`, their source modules are bound to the frozen source map, and the corresponding files in the fleet source snapshot are rehashed before either worker. The actual identity receipt is a separate SHA-identified staged input; its AA member map supplies the generator module closure. The bundle is prepared only after an actual passing CPU preflight; a template or asserted pass is not evidence.

One fleet stage uses one process group and one CPU: the parent extracts the exact common-base member, launches the pinned MAIN cache as a separately restricted packet-only decoder, checks all 480 independent-oracle fingerprints and the two decoded NPZ identities, then launches the JCV `cost_probe` for the first unit. Smoke has one DDIM step and full has three, each over every native frame and the 80 paid selected ticks. They are separate source-hidden `qualification_only` outputs, not candidate data and not a quality result. The original 24/4 context, seeds, renderer, model weights and inputs are unchanged. Both worker CPU limits and the parent CPU limit are set explicitly; the spec reserves both stage sums, smoke validator and an extra staging/monitoring/cleanup allowance. The 500-second fleet campaign budget is GPU allocation wall time, including staging, validation and publication. Exact CPU cost is charged separately, not inferred from GPU wall. The example caps are proposals, not runtime evidence.

The fleet removes ordinary scratch *before* its smoke validator runs. Before publication, each stage therefore creates an exclusive job/stage directory under host-local `w8-cost-retained`, and hard-links its newly generated NPZ, sidecar and seal plus the paid-derived checkpoint, decoder manifest and selected unit NPZ there. Ordinary scratch publication contains just the bounded JSON summary; no crops are published. The validator checks the archived summary against the retained seal and reopens the actual retained crop bytes for tick, shape and hash validation and reloads the retained packet-derived checkpoint to recheck all 480 fingerprints and the unit NPZ against the CPU oracle. This preserves the full output for later independent audit; if hard-linking or host-local retention fails, the stage fails and leaves partial evidence. Fleet automatic validation occurs only for smoke; full needs the separate `cost-audit` command after both stage `published.tar` archives and their `staging.json` receipts have been recovered into new host-local directories retaining the job ID and stage names.

The smoke gate checks isolation, oracle/weight identities and output coverage, and conservatively projects the 3-step stage against its phase limit and the actual remaining campaign clock. After the full stage, `cost-audit --one <RECOVERED_SMOKE_STAGE_DIR> --three <RECOVERED_FULL_STAGE_DIR> --oracle <ORACLE_REPORT> --remaining-gpu <SECONDS> --downstream-reserve <SECONDS> --extra-generation-overhead <SECONDS_PER_UNIT> --output <NEW_LOCAL_JSON>` independently reopens both retained outputs and compares source and device identities. It estimates the original two-unit 30-step generation using the 1-to-3-step sampling slope, measured overhead, explicit additional per-unit setup reserve and a 1.35 factor, then adds the separately reviewed native, SAM, score, staging, validation and publication GPU-time reserve. The estimate is an admission projection, not a runtime guarantee. Root must reconcile actual cost-probe and prior charges, specify every downstream reserve, and independently review the projection before authorizing any original 30-step work. A six-step cost probe, if needed, requires a separate reviewed bounded attempt; the example fleet campaign does not authorize one.

This module and template have local focused tests only; neither the two runtimes nor fleet integration has been run on Linux/GPU. No dispatch follows from this document. The exact preflight runtime allow paths, retained-file lifecycle, one-core/CPU enforcement, CPU stage timing and whole-path budget remain root review items.
