# W8 CPU-only bootstrap preflight — frozen-source proposal

This is a proposal for root review, not a submitted job or a runtime qualification. Its purpose is to run the exact `w8_receiver_bootstrap` preflight entry point once under each cached MAIN and JCV runtime, before any GPU work. The template `cpu-bootstrap-preflight-template.json` contains the recorded host paths and frozen archive/weight identities. Root must replace the two `<HOST_LOCAL_...>` values with a new host-local source archive and its matching extracted tree, review the explicit runtime allow paths against the actual host, and freeze the resulting config and its hash. Placeholder paths, missing cached files, changed identities, unknown aliases or unexpected source-archive entries fail closed. The archive SHA argument below must be the physical SHA256 of the *newly frozen* source archive from the root's exact reviewed commit; do not use mutable HEAD or infer it from the revision.

Under fresh fleet/host preflight and one-core affinity, with GPU hidden, invoke the frozen source's supervisor once from that same host-local tree (all paths are distinct, fresh, host-local and reviewed; output already exists and is empty):

```text
<MAIN_CACHE>/bin/python <FROZEN_TREE>/experiments/tennis/w8_receiver_preflight.py
  --config <FROZEN_CONFIG.json>
  --source-sha256 <PHYSICAL_SOURCE_ARCHIVE_SHA256>
  --output <NEW_EMPTY_LOCAL_OUTPUT_DIRECTORY>
```

The supervisor verifies its own file and every regular extracted source member against the physical source archive, and each loaded project module against that verified index. It makes host-local symlinks to the real source, prepared, fit, golden and mask files solely as alternate-path denied-read probes; the protected targets stay unchanged. Its first child hashes the declared MAIN/JCV and AA archives plus all eight generator weights and the five exact protected input identities, compares the AA installed files with the archive, and checks SAM installed `direct_url.json` and hashed RECORD members in MAIN. Only then does it run the MAIN and JCV bootstraps sequentially. Each receives a fresh distinct user/network namespace, a sanitized environment with `CUDA_VISIBLE_DEVICES` empty, explicit read paths, actual denied reads, closed inherited descriptors, single-thread CPU-only Torch warmup before Landlock, and a post-Landlock synthetic arithmetic check. The supervisor independently checks the receipts, actual runtime prefixes, Torch versions, loaded project module hashes, namespaces, thread and descriptor checks, denied errno values, and synthetic before/after agreement. Both output paths, child process IDs, stdout/stderr, status and resource measurements are retained. A failure or timeout stops the sequence and is not retried automatically.

Budget proposal, within the original W8 cap: supervisor ≤10 CPU-s; identity child ≤10 CPU-s; MAIN and JCV workers ≤15 CPU-s each; separate source staging, independent receipt review, monitoring and cleanup ≤10 CPU-s combined. Total **≤60 CPU-s and zero GPU-s**. Parent/children have explicit CPU limits and one-core affinity, plus 120-s individual wall limits; the operator must bound staging and review separately. These are ceilings, not a claim the work will finish within them. Source transfer, all attempts, failed checks and cleanup count. Stop before dispatch if the cumulative W8 ledger cannot reserve all 60 seconds. The 10-second identity phase hashes several large archives, weights and protected inputs and may fail or time out before reaching the workers; do not silently skip an asset, raise the limit or infer speed.

Actual archive and individual AA/SAM file matches do **not** establish that the complete extracted MAIN/JCV cache trees equal their packed environment archives. The source archive checker currently rejects non-regular non-directory tar members; if the real frozen source contains them, correct and review the verifier before execution, rather than changing the evidence. Public driver, runtime and library allow paths are proposals until verified on gpu6. A pass would establish this bounded synthetic CPU preflight only; it would not qualify CUDA devices, kernels, models, GPU isolation, output equivalence, complete receiver composition or total GPU budget. No remote action, model inference or GPU work was done to prepare this proposal.
