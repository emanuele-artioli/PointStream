# Real public folder I/O oracle (prospective)

The accepted synthetic prerequisite is `20261105T064712Z-66226a15`, revision `b805e3d2`: the real unchanged folder helper reused four regular files totaling 266 synthetic bytes, output symlink creation failed with EACCES under strict Landlock ABI 4, all ten synthetic denial probes and seven mutation probes passed, CUDA was hidden and Torch was not imported. The host-parent loader was uid 0 and the child namespace saw uid 65534 for the same device, inode and mode. Its independently checked archive/source/gate/validation and terminal-state identities are in `w8-folder-synthetic-66226a15-reference-20261105.json`; the compact audit is `w8-folder-oracle-66226a15-independent-audit-20261105.json`. This result is a mechanics upper bound only: it does not measure the real files, model loading or GPU.

The next hypothesis is that the same helper can copy, hash, reuse and safely remove the four already-declared public VAE/CLIP folder files under the unchanged strict policy within a bounded one-CPU campaign. A file-identity, source-stability, symlink-policy, namespace, disk-space, timeout or cost failure stops this phase and does not establish a model-quality negative. The oracle never imports Torch, instantiates a model or uses a GPU. The original W8 private source, four protected archives, their aliases, the other declared model inputs and all codec settings remain unchanged. The five original protected identities are stat-checked against the historic receipt on gpu6, and actual protected paths and aliases must be denied in the child; no protected body is opened by the child.

The four source files are the exact paths/SHA256s already declared for 24f, totaling **1,550,638,493 bytes** (547, 334,643,276, 703 and 1,215,993,967). Read-only metadata `w8-folder-real-io-gpu6-cache-metadata-20261105.json` observed all four cached regular files on gpu6 `/local` ext4, separate from Datasets NFS, and 3,219,480,686,592 free bytes; it did not read or hash their bodies. This is a point-in-time observation, not a current space or integrity guarantee. At runtime the four staged files must be local cache hits with exact sizes and SHA declarations; the child reads each source once while copying and checking SHA and stable file identity, verifies the copied SHA, calls the unchanged pinned folder helper, independently hashes the resulting regular files and hashes each again before deleting only the task-owned copies. Only a small receipt is published; no weight bytes are archived. The cleanup is performed only after all copies and folder checks succeed; partial failures retain scratch.

On warm local cache, two fleet staging passes each rehash the four files (about 3.10 GB combined). The worker reads another 1.55 GB of sources, reads about 4.65 GB of output copies across copy verification, helper verification and cleanup, and writes about 1.55 GB: roughly 9.30 GB local reads and 1.55 GB writes, plus source/preflight/receipt and filesystem overhead. A cold-cache fleet fallback could create a cache copy before the runner sees and rejects a non-hit; admission must verify the cache first and allow for that fail-closed behavior. The actual throughput, cache effects, local capacity at launch and cold-path cost are unknown. A synthetic 0.273-second child observation is not extrapolated to these bytes.

The [candidate spec](w8-folder-real-io-v1-spec-20261105.json) pins the four public sources, historical identity and the actual six 662 synthetic ready/state/gate/validator/published/source SHA256s. Before any copying, the runner independently verifies the selected synthetic terminal gate, policy/byte receipt and source archive; missing, modified or failed prerequisite evidence stops it. It requires gpu6 CPU-only, one core, the cached MAIN environment, at least 3 GiB free task scratch and the exact original system-file and device grants. A 120-second smoke, 20-second validator and 10-second marker fit a 180-second campaign; 60 seconds external reserve gives a proposed **240 CPU / 0 GPU seconds**. Parent/child CPU caps are 20/90 seconds and the isolated child wall limit is 105 seconds. Before copying, the runner requires 110 smoke seconds and 140 campaign seconds plus a full-stage restaging reserve, set to the larger of 15 seconds or 1.5 times measured smoke staging; it rechecks publication, validation, marker and restaging reserves after cleanup. This explicitly budgets the second fleet staging/hash pass rather than assuming the marker has no setup. Missing prerequisites, a non-cache-hit, insufficient time/space or timeout stops the run; real failure scratch is retained. The unsubmitted spec requires separate root review and a new explicit phase reservation before execution.

For any subsequent model pilot, the measured real-copy, helper-check, cleanup and whole-worker costs must be charged alongside fresh model initialization, sampling, staging, publication and independent validation. The old W8 quality and rate rules and all prior failed gates remain unchanged. Neither this I/O oracle nor the synthetic prerequisite authorizes a model or 30-step generation run.
