# W8 qualification budget artifact schema

This is an implementation contract, not an authorization, budget increase, proof or job release. Legacy schema-1 first-pilot admissions and promotions continue to use the fixed 1,500-second cumulative qualification CPU ceiling and must not carry schema-2 allowance fields. Existing per-job CPU/GPU and deadline limits, source/CPU proof, isolation, completed-artifact and quality checks remain in force.

A root-reviewed **schema-2** first-pilot admission or remaining-work promotion explicitly carries `qualification_cumulative_cpu_ceiling_seconds` (positive integer), `qualification_budget_approval_sha256` (root approval identity) and `qualification_attempt_nonce` (32 lowercase hex characters). Its existing root-pinned artifact digest is included in the fleet spec; the spec separately binds the same approval identity. The admission additionally binds `attempt_nonce` to the same nonce, `source_sha256`, `snapshot_sha256`, `cpu_proof_sha256`, `ledger_sha256` and a root-reviewed `no_prior_execution_audit_sha256`. The first-pilot guard still accepts only uniquely identified preparation charges under that nonce and rejects any tagged execution. The hash names independent canonical review evidence; it is not a substitute for root's actual review of all prior requests.

The pinned ledger contains a `qualification_budget_approvals` list with exactly one `status: approved` record for that approval SHA. The record binds `attempt_nonce`, `cumulative_cpu_ceiling_seconds`, `source_sha256`, `snapshot_sha256`, `cpu_proof_sha256`, and, for first-pilot admission, the same `no_prior_execution_audit_sha256`. The ledger is separately SHA-bound to the admission/promotion and spec; the approval SHA is an identity reference in that reviewed ledger, not a cryptographic signature verified by this module. Root must inspect and approve the referenced record and actual no-execution evidence before supplying the pinned artifact. No field or nonce may be replaced to reset prior qualification charges.

Both builders and runtime/historical validation resolve the same allowance. They require the exact set of uniquely named parent qualification charges, the same nonce for each schema-2 charge, matching charged totals, and `charged + next inclusive cap <= approved cumulative ceiling`. The next CPU/GPU caps must also fit the current remaining-unspent parent reservation; `promotion_ledger_remaining` verifies W8 and global ceilings and all active reservations. Schema-2 CPU allowance must fit the W8 workstream limit and `qualification CPU spent + parent remaining`; this is not permission to consume other future obligations. Unit-1 and finish promotion retain their normal prior-artifact and no-replay rules. Missing, null, malformed or mismatched schema-2 fields fail closed; schema-1 cannot silently carry a new limit. A direct spec ceiling is not authority.

Changing to the implementation that understands schema 2 changes source identity and requires a fresh actual CPU proof. Once that exact source and proof are accepted, a separately root-reviewed and SHA-pinned updated admission/promotion and ledger can carry a later allowance without another code change; it cannot change the proof/source identities or automatically release a job. A real previous execution, unknown request, stale ledger, budget exhaustion or missing canonical review remains a stop.
