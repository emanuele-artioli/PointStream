# Strict receiver cost pilot, fresh host identity (prospective)

The objective is a bounded measurement of the real existing W8 decoder's 1- and 3-step generation cost on one 240-frame paid unit, after a new CPU packet decode and its independent oracle checks. The hypothesis is that a fresh source-denied, mutation-confined receiver can complete both probes and provide a defensible 30-step cost forecast. Competing explanations include model/kernel, policy, source-identity, CUDA, I/O or budget failure. A missing, timed-out, invalid, nonmonotonic or over-budget result is a stop, not a quality result. No full 30-step run, encoding, model fitting or training is authorized by this proposal.

The CPU-only bd0b archived packet audit is SHA256 `c1923844722a088bbcc948c3d3d43535c31cf0440db98abbc152669287c8fc3a`: its original fleet gate failed on grant ordering and remains failed. Its separately audited packet worker used 6.426 CPU seconds and 6.531 wall seconds; those measurements bound no model cost and do not predict future NFS latency. Each proposed stage independently authenticates the old preflight and its exact required source closure, the full frozen fleet source archive, the public packet and declared model inputs. It hashes the five protected files on the actual host, verifies stable before/after/path identity and fixed historical path, SHA and inode, records host-local device numbers, and binds that new receipt to both isolated workers. The packet worker has 100 CPU / 130 wall seconds, proves its pre-serialization tensors and arrays are CPU, and its result must match all 480 fingerprints and both independently audited units before a model worker is started. Strict namespaces, 12 approved system leaves, exact file grants, all actual protected paths and aliases, mutation canaries, CPU warmup and source-only code closure remain unchanged. Fresh protected and CPU receipts are retained in the durable archive.

The prior model table documents Ada 8.9 JCV AnimateAnyone original profiles, while match5 was separately qualified on A6000; this candidate is the first strict match5 Ada cost qualification, not a carryover model-kernel pass. The actual worker must assert the Ada device, CUDA execution, loaded keys, intended modules and kernels; a generic CUDA success does not qualify the generator. The candidate is pinned to gpu6 and exclusive RTX 6000 Ada with the previously qualified MAIN and JCV archives; actual current availability and cache/host identity must be independently checked at admission.

The 1-step smoke is capped at 260 wall seconds, 3-step stage 300 seconds, and campaign 600 seconds. Reservation requested is at most 700 GPU / 1000 CPU seconds inclusive of up to 100 seconds external activity. The manifest caps parent, packet and generator at 30, 100 and 210 CPU seconds each per stage, validator at 30, and external work at 100; their aggregate ceiling is 810 CPU seconds, under its 900-second declared internal ceiling and the requested 1000. A 130-second packet plus 230-second model hard wall limit exceeds a stage cap, so these are stop ceilings, not a runtime forecast. The existing smoke gate derives a 1.35-margined 3-step estimate from actual complete 1-step stage and sampling time, accounts for staging and the remaining campaign, and stops if the 300-second stage cannot fit. No model timing is currently available under this exact policy.

After both results and an independent saved-artifact audit, the existing cost-audit command computes a two-unit 30-step projection from the measured 1/3-step slope with 1.35 margin and the measured or greater setup/decoder/publication reserve. Its `remaining-gpu` input must come from a newly reconciled authoritative W8 ledger after closing this phase, not from this document; the projection is not itself an admission. All existing physical-byte accounting, source-denial, crop/full-frame quality and guard rules remain mandatory for a later 30-step decision. Old d92/f893 failures and bd0b failed fleet gate are preserved. The candidate [spec](w8-strict-host-cost-v2-spec-20261105.json) is unsubmitted; root review, a new explicit reservation and freeze precede any job.

The pilot-specific wrapper is trusted pre-bootstrap code: it reads its SHA-bound configuration and its own public source file and checks its actual entrypoint path before invoking the existing bootstrap. It performs no CUDA operation or model-weight read before isolation; the existing bootstrap itself imports Torch for synthetic CPU warmup before Landlock. All actual model loading and inference occur inside the existing isolated receiver. After the real model probe it records the actual single CUDA device UUID, name and capability in the same child process, binds that receipt to its sealed model/kernel output and configuration hashes, and requires RTX 6000 Ada capability 8.9. The supervisor and independent stage validator compare that observed UUID to both the selected visible device and the fleet dispatch claim, and revalidate the existing model/kernel receipt. The common generator and previous model profiles remain unchanged. A later 30-step projection is explicitly advisory (`admission_authorized: false`), including when its arithmetic fits; a separate decision must verify terminal job IDs, frozen specs, dispatches, archives and the authoritative remaining ledger.

The child records its actual wrapper-relative path and source SHA in the config-bound GPU identity receipt. The supervisor and validator compare both fields with the authenticated source-only manifest, which is independently checked against the frozen fleet source archive. This does not modify or waive the historical bootstrap/preflight source closure.
