# Pre-seal metadata admission: review draft only

The proposed checker is a separate root-side admission tool, outside the scientific source snapshot. It has not run on any remote host and is not a release. It calls stat/lstat/resolve on protected targets and declared inputs; it opens only a small SHA-pinned control JSON and the new output receipt. It never hashes or opens any input, source video, golden, prepared/fit archive or mask content. The control JSON is refused before open if it aliases a protected inode.

Before an authorized run, root derives the complete exact role/path/digest map from the final immutable spec, authenticated preflight and source-transfer plan. The map covers every concrete declared input, packed environment, source archive, and actual upload/cache origin and destination. Known installed runtime and native assets use their authenticated prior manifest and cache checks; this review does not recursively attest the installed filesystem against adversarial same-user tampering. A separate metadata-only observation must record canonical regular-file `(device,inode,size,mtime_ns,ctime_ns)` for each file and the five protected targets on each machine where that path will be opened. Root independently reviews and SHA-pins this complete baseline. The native inventory's proposed shared destination is not evidence of an existing file; it must be created and checked only under a separately authorized preparation step.

Immediately before submission, the trusted host runs `preseal_metadata_check.py --baseline <reviewed-json> --baseline-sha256 <exact-reviewed-sha> --output <new-receipt>`. It compares every reviewed path and stamp against current protected identities, rejects direct paths and inode aliases, repeats all stats, records historical expected digests as references (`content_verified_now:false`), and refuses overwrites. Root compares receipt/source/spec/host to the approved submission and checks that no other fetch or source-transfer path is omitted. If the source archive first arrives or changes location after the check, repeat a fresh metadata-only check for that concrete final archive path before publication; do not treat an absent destination as verified.

The checker tests host-visible files only. Local uploader files and remote host files are separate trust domains and need separate corresponding metadata checks; installed runtime/cache identity relies on the authenticated prior manifest and fresh cache checks; a directory stat alone is not proof of its contents. It does not change fleet precheck or staging, and cannot stop a same-user replacement after the check. Under the stated trusted-controller, cooperative-immutable-input assumption, and only if the complete checked paths remain stable through every fleet open, this supports the fixed-input no-protected-content-read protocol. It is not proof against hostile swapping, changes after review, omitted paths, mount substitution, or arbitrary future requests. Those limitations must accompany any approval. Actual post-Landlock denial evidence remains a separate CPU proof, and missing/stale metadata must stop admission.

Do not run a remote observation, create the proposed destination, copy/upload data, submit a job, or run inference under this draft. Resource costs and timing for actual precheck must be reserved and charged inside the existing parent allocation before root releases any such operation.
