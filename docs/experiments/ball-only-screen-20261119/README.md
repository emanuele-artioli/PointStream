# Ball-only reconstruction at three rates

Freeze the existing three plain AV1 base packets and their serialized ball sidecars before measuring regional quality. Reconstruct the complete 240-frame stream at each existing CRF 36, 48 and 60 with no generated players, retaining original foreground in the base. Save exact RGB pixels for the 12 source-reviewed ticks 10, 30, 50, 70, 90, 110, 130, 150, 170, 190, 210 and 230. The sender-detected ball positions and paid AV1 tiles are unchanged. Check the authentic packet and sidecar hashes, decoded base YUV hash, tool identity, 240-frame count and full output RGB hash against their earlier records, before reporting. The parent experiment can score the same player and ball labels on the same frames against the added-player outputs, at matched total rates.

The experiment uses one opened development rally and does not create confirmation evidence. Total rate includes the actual native packet and complete ball sidecar. Encoding initialization is charged to the 4.8-second rally. The original AV1 base still contains the source ball and players, and the separate channel overwrites the 32×32 ball patch only when its detector has a placement. Local CPU budget is 180 seconds, no GPU. Report the preexisting complete stream rates for all three settings and preserve source data.

The replay succeeded. Complete native-plus-ball packets cost 670.197, 336.178 and 158.738 kbps at CRF 36, 48 and 60 respectively. All 240 reconstructed RGB frames per rate matched the earlier stream hash and each saved PNG decoded to the exact selected RGB frame. The 36 frames and receipt are in `/private/tmp/ps-regional-ball-only-frames-20261119`. Main Python process CPU was 18.16 seconds and wall time was 19.85 seconds. Decoder subprocess CPU was not included in that measurement. No GPU was used. The [receipt](receipt.json) records each PNG hash and ball position.
