# Transfer beyond tennis

The architecture requires a shot decision, an object signal and a receiver representation. The three parts can be evaluated separately when a new domain lacks a complete receiver. The paper’s main experiment estimates tennis foreground fidelity. A cross-domain comparison earns a place in evaluation when it answers which representation works under a different camera or object regime. The datasets alone support no coding claim.

## Egocentric hand–object video

Four saved VISOR windows provide an informative metric and rate-accounting check. With source shape available to both sides at zero rate and matched adaptation, the split representation used 15% less rate at equal weighted DISTS against venue-adapted DCVC-UF and the best tested per-rate selection used 6% more at equal weighted LPIPS. The fixed construction used 16% more on that metric. Full-frame LPIPS also favored DCVC-UF. This is a conditional comparison on an older pixel-split method. A follow-up using receiver masks and billed inputs failed its predeclared weighted-DISTS criterion. The one small-foreground win under an older paid-mask construction was retrospective and did not transfer to the whole selected set. The later fixed-patch study needed 18.47% more rate than its conventional anchor at equal weighted DISTS. These results identify shape overhead, moving backgrounds and hand–object boundaries as testable reasons the representation may behave differently. Keep the egocentric result concise in the appendix and explain the domain choice in the discussion. Reuse the official active-object annotations and the existing source-only review packet. The first 18-frame review approved zero final masks. Before trying a new generator, do a bounded CPU oracle on a few official, source-aligned VISOR frames: charge the actual shape and updates, let an ideal sender use independent hand/object labels, and compare against matched AV1 on the hand/object region and on the full frame. Move to a paid-packet prototype only if there is a rate–quality headroom at a common operating point. ## Other racket sports

Table tennis is the nearest inexpensive transfer test because OpenTTGames supplies 120-fps video, ball coordinates and event intervals. In the existing background experiment, a single homography explained 99% of matched static points at one second across seven fixed-camera clips. The tennis WASB judge, however, yielded 0/85 visible hits and 0/6 false emissions on the one reviewed OpenTTGames context. Its video–label join was checked on native frames. That makes this a geometry and source-domain result. A compression test should first use the exact saved source join and official coordinates in a short CPU position oracle. Freeze the frame indices and visibility before inspecting the videos. At fixed total bytes compare the complete AV1 base plus charged trajectory with ordinary AV1. Show labeled ball-crop fidelity and whole-frame quality. Separate the oracle from automatic tracking. Extend to a sport-appropriate tracker and an independent judge only if the oracle gives a reason. [Static camera results](../g1e.md) · [Reviewed source and judge gate](../k5d-ball-benchmark.md) · [OpenTTGames and TTNet](https://openaccess.thecvf.com/content_CVPRW_2020/html/w53/Voeikov_TTNet_Real-Time_Temporal_and_Spatial_Video_Analysis_of_Table_Tennis_CVPRW_2020_paper.html)

Badminton is a distinct test of airborne motion, occlusions and a shuttle's appearance. The installed RacketVision dataset gives badminton shuttle and racket marks. Use the same one-short-shot oracle only after the table-tennis test establishes the interface and score. Player generation in either sport can follow a successful paid object stream. Cameras, foreground identities and backgrounds can each change independently. [RacketVision](https://arxiv.org/abs/2511.17045)
