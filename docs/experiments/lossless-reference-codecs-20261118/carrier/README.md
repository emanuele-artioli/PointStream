# Lossless player-reference packets on the development rally

Before running the packet comparison, keep the approved player conditioning fixed. Repack the first 480×272-base player carrier and the 960×544 CRF48 carrier using the smaller exact reference formats. Count each complete carrier and its receiver manifest. For the second carrier, rebind the original ball tile and its 240 placements and charge the complete sidecar. Charge all initialization to the 4.8-second rally. The decision is to use the new profile only when the entire carrier shrinks and both players' decoded appearance, poses, boxes, timestamps and seeds match the prior full receiver. Small images or extra profile metadata could favor the old carrier. Limit this check to two existing carriers, 120 campus CPU-seconds and zero GPU. Full video generation and scoring are outside this comparison.

## Results

On this 4.8-second rally the new sender selected lossless WebP for both players. The complete reference sections fell from 365,939 to 242,343 bytes. After charging the new packet header, the reference change saved **123,253 bytes** in each player carrier. The figures below charge both appearance references once during the rally.

| Delivery | Original bytes | New bytes | Original kbps | New kbps |
|---|---:|---:|---:|---:|
| 480×272 base and two players | 392,423 | 269,170 | 654.04 | 448.62 |
| 960×544 base and two players | 552,516 | 429,263 | 920.86 | 715.44 |
| 960×544 base, two players and ball | 571,630 | 448,376 | 952.72 | 747.29 |

A separate CPU receiver for each carrier opened only the delivered files after loading the runtime. It ran in a fresh Linux network namespace with Landlock ABI 4 and confirmed that the original PNG carrier was inaccessible. For each player, the decoded reference, 240 pose maps, 240 boxes, timestamps and seed matched the earlier full receiver. The coded base and keypoints were byte-identical. The joint receiver authenticated the same tile stream and 240 positions, including 195 placements. Its rebound sidecar was one byte shorter because the NumPy version string changed from 1.26.4 to 2.5.4. The joint saving was therefore 123,254 bytes in total. These measurements cover the serialized delivery and the inputs to rendering. The playback videos were produced with the earlier PNG carriers. This CPU check stopped before video generation and quality scoring. Reusing references across more shots would spread the fixed saving over a longer duration.

The sender entry point is `experiments.tennis.common_player_packet.optimize_lossless_carrier`. It accepts a PNG player carrier, tries exact reference encodings, includes the decoder identity and pixel hashes, and keeps the original carrier when it is smaller. Lossy AVIF remains a candidate for images previously delivered as JPEG. The prior two-image experiment measured the decoded reference image. A generated-player comparison is still needed before adopting lossy AVIF for player conditioning. [Prior lossy comparison](../lossy-result.json)
