# Native lengths in the six held-out tennis points

The six TenniSet intervals contain 106, 132, 144, 120, 138 and 264 original 1280×720 pictures at 25 fps. Their durations are 4.24, 5.28, 5.76, 4.80, 5.52 and 10.56 seconds. A 20.4 kbps per-rally cap therefore admits 10,812 to 26,928 bytes. The 33 kbps cap admits 17,490 to 43,560 bytes. Derive the amount from the individual native interval and count every delivered picture. [Original cohorts and route rules](README.md)

## Three delivery paths

| Path | Existing support | What it can establish |
|---|---|---|
| Keep the common 240-frame player profile | Valid for the original 240-frame receipts and a 120-frame active player interval embedded in an actual 240-frame mixed stream | Preserves historical evidence. Require an oracle using the actual source and exact length to show a potential foreground advantage before building this path. Preserve old reader paths and their packet, crop and display hashes. |

## What the variable-length joint path requires

1. Bind immutable native interval, native geometry and exact cadence from source screens through feature extraction and crop-pose receipts. The current `test_joint_features`, `test_crop_pose` and sender require 240 ticks and use 1080p geometry. The low-level `k4b_pose` helper also contains fixed 1080p shape assumptions. Keep coordinate transformation and masks explicit at this boundary.
2. Introduce a versioned variable-length recipe and outer profile before changing accepted packets. Validate one common `native_frames` value across the declared recipe, IVF header and timestamps, KPS metadata, distinct runs, cuts and coverage. Both the `common_player_packet` bounded KPS2 reader and the older KPS1 transcode validation are capped at 240. A versioned path needs an explicitly bounded 264-frame contiguous run. The W2 range code itself already stores run lengths as varints. Keep the old validation and old packet identities. [Player carrier](../../../experiments/tennis/common_player_packet.py) · [Keypoint transport](../../../experiments/tennis/k6b_rate_streams.py)
3. Carry output length and geometry through generation conditioning, fleet job stages, resource limits and forecasts. The renderer takes `len(poses)` but `common_receiver_generate` and `common_receiver_job` accept only 120/240 full continuous runs, with older qualified prefixes. Scope generation to actual active intervals. Forecast from production-shape pilot timings at the chosen length. [Generation conditioning](../../../experiments/tennis/common_receiver_generate.py) · [Current fleet validation](../../../experiments/tennis/common_receiver_job.py)
4. Generalize the source-denied finisher and scorer together. The outer `med_mixed_channel` currently binds a 1920×1080 display, 960×544 ball layer and fixed total and active windows. `k6b_receiver_sam.project` allocates a 1080p mask even though the final paste already takes the canvas dimensions. Preserve actual frame count, clipping rules, full-canvas hash verification, conventional frames for each inactive tick and immutable fallback time. Require independent native-tick joint and control receipts on the same source supports. [Mixed channel](../../../experiments/tennis/med_mixed_channel.py) · [SAM projection](../../../experiments/tennis/k6b_receiver_sam.py) · [Shape-generic paste](../../../experiments/tennis/k6b.py)

These are four distinct integration stages. The fastest experiment for the missing evidence uses the existing native/ball route and its physical controls first. A fair upper bound for player extension is the existing source-supported conditional foreground oracle on the original new length and display, charging at least the measured trajectory, base and necessary conditioning bytes. Use the route choice selected before inspecting decoded quality. At a minimum, test old 240-frame parity, 106 and 264 frame extremes, absent tail, cut/run consistency, the same 25 fps, and source-denied final image reconstruction on a real held-out point before extending any player claim.

## Real local transport smoke

The shortest and longest source-frozen clips passed actual stock SVT-AV1 encoding and native dav1d decoding at 1280×720 and 25 fps for all 106 and 264 native ticks. The smoke rechecked the ordered hashes of every lossless source YUV frame. It independently decoded the AV1 carried by PSBL and obtained the same complete decoded YUV hash as PSC1 for each rally. Arbitrary markers on the first and last frames changed RGB pixels at those frames. Three sampled absent frames matched the decoded base. The markers intentionally bear no relationship to a ball. The proof used CRF42/preset12 and supplies neither a starved matched-rate result nor a tracker or quality comparison. The separate low-rate conventional preflight selects actual controls.
