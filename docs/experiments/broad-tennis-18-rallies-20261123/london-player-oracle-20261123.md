# London native player pilot preflight

## Question and precommitted decision

On the shortest enrolled London rally, can a two-player native stream fit the existing 20.4 and 33 kbps ceilings and improve measured body quality on the eight frozen source instants? First recover all existing source supports and coded rates. Compute the maximum remaining bytes for a player-conditioned stream using the real ball-plus-base packet. This accounting is a feasibility diagnostic, not a player encoder or an upper bound on attainable quality. The sender may lower its base rate to make more space. A positive residual therefore does not establish feasibility and a negative residual for this single base does not exclude another base.

An ideal player reconstruction, with source pixels available at no rate, is a fidelity ceiling only. It trivially has zero error on the accepted source masks, so it cannot qualify a real learned player. To promote the native joint path, extract actual London poses and references, pay their serialized bytes and initialize costs, then replay both actual rendered players and count all 106 source ticks. Before any GPU run, qualify source geometry and native cadence, compare a 24-tick real player smoke with existing timing, and forecast each role. Include decoder, masks, ball, native base, fallback and all framing. The aged packet, renderer and scoring wrappers fix 240 frames and 1080p. Adapt them through an explicitly versioned native profile and verify legacy hashes before using new output for evidence. If any input is missing or the forecast fails, preserve the result as a preflight and revise the approach.

Existing 106-frame source has SHA-256 `8ab59163aa86f3cb0f26b1981e6e546f148cca916e40731c0cdee5c6621e4b78`, 25 fps, 1280×720. All 106 ticks passed court-view eligibility. The source review supplied two accepted player proposals at each of eight frozen instants. These are useful for regional appearance metrics, and are not independently annotated ground truth for silhouette IoU. Two independently marked visible balls had no sent position on this point. Three assisted visible marks must remain separate.

## Result

The six frozen stream/score ledgers reproduced the full-byte headroom and per-frame body metrics. In the shortest rally, the 20.4 kbps ceiling is 10,812 bytes and the existing ball-plus-base stream uses 9,778 bytes. The remaining 1,034 bytes would also need to cover player transmission and any added framing. At 33 kbps the corresponding figures are 17,490, 12,894 and 4,596 bytes. The 16 accepted proposal instances across its eight reviewed frames give mean body DISTS 0.410 and 0.386 for these two saved displays. This is a fixed-base baseline, with no headroom reserved for a player. The original native fallback and body scores on the remaining five rallies are retained in the [receipt](london-player-preflight.json).

The full 106-frame player input is not available in the reviewed labels. The checked proposals span eight frames, so they cannot supply the learned receiver's per-frame masks or pose conditioning. The automatic source feature worker hardcodes 1920×1080 and 240 frames, and the player carrier and source-denied compositor enforce the same interval. Up-scaling or padding the original input would introduce a new experimental path that still needs source-grid geometry, validated interpolation and byte accounting. The existing 106/264-frame video-and-ball smoke therefore does not qualify the player path. Prioritize actual source-only feature extraction on the 106 ticks and compare all output times and geometry to the source before assigning player generation.

## Source-only player detection pilot

Before player generation, test whether the already installed YOLO26n-seg model can locate candidates on the shortest rally's original native 720p pixels. Use its previously frozen weights, CPU, 960 input, person class and confidence 0.18. Initialize two athlete boxes at reviewed tick 6 from the accepted source proposals, then link forward and backward by nearest center normalized by box size, one-to-one, with a distance cutoff of one box diagonal. This is an exploratory tracking method and uses a source-reviewed seed. Compare the linked boxes against the eight selected reviewed proposal boxes using center separation normalized by the reviewed diagonal and a 0.5-diagonal pass threshold. Report missing assignments, identity mismatches and labels separately. This is a candidate-coverage and association diagnostic, with reviewed proposals treated as references, not per-pixel ground truth. A result with fewer than two viable candidates for any scored frame or a mismatch is a signal that the naive method needs improvement, not proof the production SAM tracker fails.

Use a 24-frame smoke to validate finite boxes, source identity, runtime and sample records. Forecast the complete 106-frame CPU inference at 1.5× the observed per-frame time plus 30 seconds. Run the full source only if forecast is under 10 CPU minutes. Keep separate output receipts and no GPU.

The 24-frame smoke linked both athletes on all 24 frames and matched the two frozen source proposals. The forecast was 48.3 seconds. The 106-frame full run finished in 11.7 seconds, with 93 linked frames and seven of eight reviewed instants agreeing. One link failed in the final section, so this rule does not establish a usable complete player track. This uses a manual source-box seed and the same model that generated the reviewed proposals. The numerical agreement does not provide independent ground truth. [All candidate boxes and identity checks](london-source-detection-106.json)

Test one bounded recovery on those saved detections without rerunning the detector. Retain the most recent observed box for a missing person for up to three ticks, while reporting that track as missing on those ticks. Accept a later detection within the same one-diagonal rule. Keep role assignments and all eight proposal comparisons. Do not interpolate or count unobserved masks as actual tracks. If this fails to retain both tracks at a reviewed instant, record the failure and leave the player stream ineligible until a proper tracker recovers it.

Recovery supplies observed detector boxes for 104 of 106 ticks, with missing ticks 93 and 96. It reacquires the source-proposal match at tick 99 and agrees with all eight selected proposals, but both this association and the assessed proposals use the same detector. Missing ticks are not interpolated and the reviewed seed is not a deployable automatic initialization. [Recovery receipt](london-source-link-recovery.json)

For a conservative fallback test, stop the tentative player interval at the first lost player proposal, tick 93. Encode ticks 0–92 and 93–105 as two independent native 640×360 SVT-AV1 streams at preset 4, CRF 70, the existing shortest-point 20.4 kbps base setting. Package both with PSC1 and require 93 and 13 decoded frames respectively at 25 fps. Count both packets' bytes and compare against the original 10,812-byte whole-point budget. This prices a real split conventional path and shows the extra restart cost. The prefix still contains source players and is not a cleaned or reconstructed PointStream base. Player, ball and higher-level switching bytes are not yet included. The result is only a cost probe. Use the source-derived input already encoded in the previous 640-pixel bank, check source and raw hashes, and use a 2-minute local CPU cap.

Both physical PSC1 packets were decoded on all 106 native ticks. Their sizes were 8,896 bytes for 93 ticks and 2,957 bytes for the 13-tick fallback, totaling 11,853 bytes. That exceeds the 10,812-byte ceiling at 20.4 kbps by 1,041 bytes before any ball or player payload. The original unsplit AV1 IVF used 9,467 bytes, which omits PSC1 framing. At 33 kbps the total is within the 17,490-byte ceiling by 5,637 bytes before the missing components. These rates belong to the actual conventional input at CRF70. A cleaned and reallocated prefix or a different fallback quality could change the result. [Byte counts, source identity and full decode hashes](london-split-cost.json)

## Matched-rate ball display controls

The production player path needs a new native 720p feature worker, paid poses and a versioned receiver before it can produce defensible evidence. While that work remains open, use the three frozen London points V006/14, V006/41 and V007/65 to inspect saved ball streams at 20.4 kbps, with two matches represented and two independently marked visible frames per point. Retain the independent and assisted marks in separate strata. Select the physical conventional AV1 packet closest in size to each saved ball packet by byte count alone. Limit the search to the 640×360 codec setting already selected for each ball stream, preset 4, on the exact native source. Test fractional CRF by bisection with at most nine encodes per rally and stop within 0.5% of the ball packet size. Keep an achieved point if it misses this threshold and flag the gap.

On the original frozen source frames, evaluate DISTS, LPIPS, SSIM and PSNR on the same independent visible ball crops, assisted visible crops and accepted player proposals. Separately compare whole-picture PSNR and SSIM across every native frame. Preserve all non-court fallback time and compare delivered bitrate with actual packet bytes. The independent clicks were preferentially available when no tracker suggestion was shown. This diagnostic is not an unbiased detector-recall sample. Budget 20 local CPU-minutes, no GPU.

The three 20.4 kbps byte-only searches returned ordinary AV1 packets 1.32% below, 0.56% above and 1.43% above the respective ball packets. All six packets fit their individual available budgets. None met the predeclared 0.5% match, so these are diagnostics and should not support a tightly matched headline. The first attempt tested an invalid CRF above the encoder's supported maximum of 70 and was rejected before encoding. The corrected bounded search completed in 242 seconds wall.

On all six independent visible marks in this selected sample, the ball sender emitted no point. Mean ball-crop DISTS was 0.2995 for ordinary AV1 and 0.3094 for the ball stream. On eight assisted visible marks, DISTS was 0.3118 and 0.2905 respectively. The assisted subset is selected by tracker suggestion availability and is not independent. All-frame ball-stream PSNR fell by 0.157, 0.246 and 0.103 dB in these three points, respectively. This is a camera/event transfer diagnostic, with two points from one match and a third from another match in the same event.
