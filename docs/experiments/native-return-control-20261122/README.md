# Can an ordinary AV1 decoder reuse a court view after a cutaway?

Freeze the 245-frame, 50-fps source-only presentation copy of the already studied Nadal court / close-up / court passage (SHA-256 0d20d883430ecfea33c474f7e7c7f42df6052437898d390af254148def687b50). The original master is unavailable locally. Both arms see the identical downscaled 320 × 180 YUV for every tick. This is a conventional-codec diagnostic on this derivative, which cannot be joined numerically to the native 1080p plate study.

Use stock libaom in low delay. In both arms slot 0 holds the previously decoded frame, and the decoded last court frame before the cut is retained in slot 1. Permit optional GOLDEN prediction from that slot during the 100 returning court frames in the test arm; the control can use only LAST. Every other setting, including random access at the first frame, is identical. Compare complete IVF bytes and independently decoded luma PSNR for the return and full passage at Q35, 45 and 55. The hypothesis is that keeping the pre-cut court view reduces bytes at equal return quality even for a conventional codec. The competing explanation is that camera/foreground motion makes a distant picture too stale. This tests native tool availability and measures an achievable control conditional on a known return boundary. It does not estimate product adoption or attribute a benefit to PointStream.

Smoke with the true three-shot transition and Q45, require complete 245-frame decoding and bit-exact pre-return payloads across arms, permit identical outputs if the encoder ignores the extra reference. Add the other two settings only if the six encodes and validation fit 300 local CPU-seconds and 10 minutes elapsed. Stop after this one transition. Future comparison with PointStream and the normal unrestricted encoder must use native footage, equal output quality, the same random access schedule and a paid foreground.

All six native streams decoded with dav1d. The compressed bytes were identical across arms for the first 145 ticks at each quantizer. When both references were available for return, the encoder spent 69,889 versus 71,471 bytes for the whole passage at Q45 and achieved 31.112 versus 30.762 dB on the return. Over the overlapping ranges, the extra pre-cut reference saved **4.84% of complete bytes at equal whole-passage luma PSNR** (28.09–35.10 dB) and **13.84% of return bytes at equal return luma PSNR** (27.70–34.47 dB), using the project's upper anchor envelope and log-rate PCHIP integral. This is evidence that an ordinary AV1 reference is a meaningful comparator on this passage. No PointStream foreground was encoded here. [Native tools, commands and per-stream receipt](result.json)

Run with `PYTHONPATH=. python docs/experiments/native-return-control-20261122/run.py FRESH_DIRECTORY` using libaom 3.14.1. The standard rate calculation is `experiments.background.g5.bd_rate(test_points, envelope(anchor_points))` with byte count and PSNR for the stated interval. The measured local CPU use was 5.04 seconds.
