# Experiments: paid common-tennis player receiver design

**Design only. No code, additional compute, model fitting, evaluation, or budget is authorized by this draft.** Player 2's one-author, unpaired acceptance of 240 generated crop frames on the opened Nadal–Kyrgios development source motivates a player-only receiver witness. It does not establish a codec gain, a complete receiver, a ball result, or source-level generalization. Player 1's outcome is independent and remains pending at drafting.

### 2026-11-17 — unreleased receiver contract draft

## Hypothesis and decision boundary

Hypothesis: a receiver using only a paid native full-frame base, paid reference crops and paid quantized keypoints can reproduce the accepted common-tennis candidate and compose generated players on every native frame without source-side masks. Competing explanations include missing or incorrect receiver silhouettes, pose/reference distribution mismatch, base artifacts, and transport overhead that erases any quality advantage. Separate the functional receiver witness from the subsequent matched-rate quality decision. Reuse valid packet/renderer qualifications in their exact scope; local serialization and fallback implementation need no invented perceptual upper bound. A new scientific component still requires the project's applicable oracle, with explicit dominance; source-pixel replacement is not a universal LPIPS/DISTS bound. Freeze exact exposure, inputs and a separate costed GPU stage before execution. A valid witness establishes correct reconstruction and accounting; it is not itself evidence of a bitrate win.

## Smallest proposed new profile

Add a **new versioned common-tennis window profile**; preserve the existing W8 wire format, profile identities and historical results. The outer packet carries a real native full-frame AV1 IVF stream, KPS2 quantized track bytes, one paid encoded RGB reference per active player, and the minimum explicit timing, crop/run, compositing-order and profile/model identity metadata needed to decode. Account for actual encoded bytes, all framing and all window/reference charges, and amortization only when actually justified. Keep the installed shared tennis checkpoint/LoRA and pinned original model weights as declared receiver model state; verify their hashes and account for deployment/model cost under the declared convention. There is **no match-specific checkpoint, adapter or guider update** in this profile, and no invented zero-cost match state. Fix CFG3.5, 30 steps, context24/overlap4, model version, seed rule and all source-independent transformations in the new profile. Do not carry a tensor of RGB pose maps as a substitute for compact paid KPS2.

The existing `w8_payload.pack`/`unpack` checks section framing and hashes, but `unpack_window` hard-requires match5, CFG2, match bytes and only every-third saved tick. Define a separate strict validator and builder; do not relax or relabel it. `k6b_rate_streams.encode_keypoints`/`decode_keypoints` already define q4/every-four coordinate samples, interpolation, every-frame visibility and run timing; `encode_reference`/`decode_reference` support paid reference bytes. `w8_inputs.decode_inputs` reconstructs poses and boxes from those bytes, but its frozen W7 metadata/profile assumptions and two-unit contract must be explicitly versioned for the new candidate. Demonstrate byte-decoded references, per-tick poses, boxes, run IDs and seeds match the authenticated candidate conditioning where reused. Quantization, interpolation, visibility, geometry, source frames and paid tick coverage must be verified, not inferred from a shared label. The exact native base, KPS2/reference assets, their compatibility with this source, and the intended player count remain to be authenticated; do not assume they exist merely because a prior W8 packet exists.

## Receiver behavior and completeness

The isolated receiver accepts only the packet, explicitly installed hash-pinned model/decoder dependencies and declared execution code. It must not read source footage, cached golden crops, source masks, or teacher annotations. Reuse the isolation and input-closure approach in `w8_receiver_generate.run_packet_isolated`, `run_isolated`, and `w8_strict_source.stage_source`/`verify_source`, subject to a fresh access-denial audit. Decode the paid IVF with a pinned native decoder; `w8_receiver_finish.native_argv` currently pins a specific old IVF, so adapt it under the new profile rather than silently reusing that fixed identity. Verify decoded dimensions, frame count, timestamps, cadence and color conversion, including decoder version and all bytes consumed.

Render each contiguous decoded player run in a **single call per run**, preserving the seed rule and all actual per-tick outputs. `w8_receiver_generate.render_full_unit` renders complete runs but deliberately retains only the judged every-third frames and requires exactly 240 inputs; it is not an every-frame endpoint. Implement and validate an explicit all-frame output contract, with no independently generated 24-frame concatenation. Memory and runtime on the target host must be measured; do not assume smoke pixels match the full-run prefix.

Generate masks on the receiver from generated player crops and paid keypoint prompts, with the selected installed mask-model identity and inference policy pinned. `w8_receiver_finish.run_sam_isolated` and `k6b_receiver_sam.pose_prompt`/`project` show relevant primitives, but the W8 implementation selects historical ticks and fixed units and is not already an all-frame receiver. Verify one receiver-generated mask per generated tick, geometry and predicted support, with no source-derived matte. A bad or empty mask must be detected/reported; the exact fail-closed versus base-only rule and whether a paid presence/validity flag is needed must be decided before the experiment, not tuned on its outcomes.

For every output tick initialize from the decoded native base, and paste only valid generated crop pixels within projected predicted masks in a declared far-to-near order. `k6b_real_base_compose.compose` preserves base pixels outside written support; a missing crop or box leaves the base intact but its current API still requires a mask per declared player. Explicitly define and test the new absence/missing-data path rather than assuming the old endpoint handles it. At track gaps, cuts or player absence, reset temporal context and do not hallucinate across runs; retain native base in absent/invalid regions. Specify reference renewal, track identity/order, cut signaling and whether they are paid bytes. Reject missing coverage or unsupported changes instead of labeling a partial reconstruction complete. Output a complete native-resolution, native-cadence 240-frame sequence plus per-frame coverage and content hashes; count masks/crops as intermediate receiver outputs, not free transmitted content.

## Qualification and cost before any release

1. CPU-only contract checks: round-trip and corruption/truncation/extra-section rejection; exact byte accounting; identity closure; no match bytes; paid reference/geometry joins; every-frame timestamps and run boundaries; no hidden source access; box/mask projection, order, gaps, cuts and base fallback. Compare packet-decoded conditioning with the retained real candidate arrays, including run/tick boundaries and seed, not just hashes of metadata. Establish source dimensions and source/packet timestamp joins. Test the native decoder and color path on authenticated inputs.
2. Before GPU execution, write the hypothesis, competing explanation, stop rule, applicable component-oracle evidence and budget in the experiment card; check existing fleet jobs and qualified hosts. A bounded real correctness smoke must use the intended packet, installed checkpoint, isolated process, exact native path and representative geometry; validate device, dtype, actual attention/kernel path, model lineage, every output, memory, masks, denied source reads and teardown. Reuse unchanged model/GPU-class qualification from the fleet table rather than reopening it. No stand-in establishes evidence.
3. A bounded cost pilot must include generation, actual receiver-side masks, base decode, composition and publication—not just generator time—and show the declared stage and campaign caps can finish. Break each waited stage into recoverable parts of at most 45 minutes, retain every finished unit and stop at a failed gate. The observed amended 44-frame smoke render (~218.8 s) and one 240-frame Player 2 render (~932.7 s) are shared-GPU feasibility leads for the crop renderer only, not complete-receiver cost, a throughput benchmark, or an authorization. Full-frame intermediates, masks, CPU decode and both players can materially change memory and cost. No retry or scale-up is implied.
4. After applicable component-oracle evidence, smoke and bounded pilot pass, promote a frozen player-only witness and a separate matched-rate comparison. Report actual packet/header/reference/model allocation, decoder and encoder paths, inputs, code, device and quality evidence; use an achievable anchor envelope and BD-rate only across overlapping quality ranges. Start with three base rates. The generator currently consumes reference and poses rather than the native base: identical reference/pose/model/seed identities can permit one generated sequence and its masks to be reused across base rates, with every resulting composition and byte total verified. Do not regenerate merely because the base rate changes; changing coded references or conditioning invalidates that reuse. Include effective ROI/DCVC and an appropriate generic enhancement control. Judges must not have seen evaluated frames. If masks fail or overhead dominates, report the failure and narrow the claim before proposing repair.

## Open decisions and boundaries

- Choose the actual base encoding/rates and reference coding; validate that the needed packet members and native files are available and legitimately bound. The common LoRA remains a declared installed resource under the current policy, with footprint/cold initialization and historical charged-model sensitivity reported. Decide the smallest supported number of players and behavior when tracks do not cover every frame. Count startup before another expensive quality test: retained W8 reference bytes alone are366,161B, or610.27kbps over4.8s. This is a retained-input cost diagnostic, not a new common-profile packet rate; its header and assets still need serialization. Cheaper reference coding changes conditioning and requires a new declared pilot. Longer reuse is a sensitivity until actual reference validity, refreshes and duration are demonstrated.
- Freeze mask model, deterministic prompting, empty-mask behavior, confidence/validity signaling, cuts/identity/reference-refresh costs, and resource budget. Prove isolation supports all necessary file and MCP restrictions; otherwise run attended.
- Select a predeclared player-only oracle, anchor, metric/acceptability rule and exposure split before looking at new outcomes. The accepted Player 2 crop is not a source-independent visual quality or matched-codec result.
- Ball is a separate same-source gap: authenticate its actual stream and source-only references, then pay and validate its receiver path before any player-and-ball claim. The player-only witness cannot stand in for combined decoding.
