Question for the cumulative joint figure: can a 20 kbps total budget plausibly carry the actual 50-fps Nadal /000 to /002 interval while the gap is routed wholly through a conventional codec? At 20 kbps, the complete interval has 565,250 bytes, leaving 322,250 bytes for all other video, motion, ball and packet overhead. The cheapest decision stage is an actual low-rate fallback measurement, not a claim that a particular operating point is the global minimum. Run the entire 10,825-frame gap through native SVT-AV1 at 240×136, 50 fps, preset 8 and CRF70, with one 50-fps frame per input tick. Use one core, a 300-second smoke, a 1,800-second full stage and 2,400 total CPU-seconds, including staging and independent validation, with zero GPU. Preserve data and intermediates in campus fleet storage or host-local scratch. Target 20 kbps because the prior successful historical player point was 19.24 kbps.

Hypothesis: a whole-gap fallback at this aggressive operating point consumes less than the 322,250-byte budget, leaving room for actual rally objects. Competing explanation: even this aggressively quantized and downscaled real fallback exceeds the remaining bytes. If actual reference initialization plus fallback IVF already exceeds the whole target budget, this exact fallback configuration cannot reach 20 kbps with any positive-size rally payload. A higher total bitrate or a different fallback representation remains open. If it fits, measure its quality, actual clean-base/player/ball packets and receiver switching before making a combined result. The 240×136 fallback is an intentionally extreme feasibility probe, so a passing rate alone does not establish acceptable picture quality.
