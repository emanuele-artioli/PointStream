# PointStream paper figures

PointStream splits a broadcast at scene cuts. On suitable shots, the sender can describe foreground motion with points and transmit appearance where needed. Other shots use a conventional codec. The research question is which representation makes the best use of a given bandwidth budget for a viewer or a machine. Keep system design general. Tennis provides the principal evaluation.

## Manuscript sequence

| Order | Reader question | What earns the page |
|---|---|---|
| **1 · Introduction** | Why send points when the viewer wants video? | Show a real rally, cutaway and return. Enlarge a player and ball on the original rally. Use matching decoded crops to show what a few extra object bytes buy. Identify actual source cuts and label routing illustrations. [Timeline and crops](docs/paper/figures/system/README.md) |
| **2 · Architecture** | What does the server send, and what can each receiver use? | Trace eligibility, conventional fallback, points, appearance, base updates and cached state to a displayed frame. Branch the object signals to an application before RGB feature extraction. The tennis implementation supplies two [algorithm boxes](docs/paper/figures/system/algorithms.md) on court eligibility and per-tick tracked-pixel delivery. Keep adaptive rate selection labeled as a proposal until tested. [Architecture](docs/paper/figures/system/architecture.pdf) |
| **3 · Lead result** | At a given total bitrate, which pipeline preserves the foreground? | Plot measured bitrate on x and the same registered quality objective on y for each pipeline. Label a single measured configuration as a point. The [regional draft](docs/paper/figures/selection/rate-quality.pdf) covers one cold-start rally. To finish, compare complete PointStream, AV1, ROI and DCVC on the same Alcaraz window at 20/50/125 kbps where feasible; charge cold and observed reuse separately. Freeze before new matches. [Missing data](docs/paper/figures/selection/README.md) |
| **4 · Displayed ball** | What do viewers gain or give up when bits move to a small object? | Pair actual decoded crops with the [equal-budget fidelity figure](docs/paper/figures/ball/matched-rate-ball-fidelity.pdf), and use the [three-match equal-quality result](docs/paper/figures/ball/three-match-ball-bd-rate.pdf) for generality across the measured sources. Report player and whole-frame costs. Keep detector outcomes in their own figure. |
| **5 · Machine tasks** | Can software use the same stream directly, and how does that compare with inferring features from decoded video? | Use complete stream rate on x. Show direct coordinates and receiver-derived signals separately. Compare against the same RGB judge on PointStream and conventional outputs. First close [ball localization and absent-frame errors](docs/paper/figures/ball/README.md) at matched rate; then score [segmentation](docs/paper/figures/player-tasks/README.md) against reviewed masks. Add pose accuracy only with human joint labels. Record time to usable features. |
| **6 · Cost and reuse** | Why does one pipeline win on one passage and lose on another? | Show the [measured startup byte breakdown](docs/paper/figures/system/byte-budget.pdf). Add an actual warm return with references, cutaway, refreshes and every emitted frame. A short table should give source/cadence, duration, known receiver assets, training exposure and cold/reuse assumptions for each family of results. |
| **Appendix and conditional promotions** | Which details affect the decision? | Put the retrospective per-object bandwidth strip, [background fill diagnostic](docs/paper/figures/background/README.md), [still reference codec ladder](docs/paper/figures/references/README.md) and pose coding error in the appendix. Describe donor alignment and hole filling in the method. A matched complete-stream gain can earn a main-text background result or a rate-dependent reference policy figure. |

## Order of work

1. **Finish the lead rate–quality figure.** Its x-axis charges the complete stream. Its primary y-axis uses the registered 70/30 foreground/complement DISTS objective, with LPIPS, both player bodies, ball, complement, whole frame and temporal behavior beside it. Keep cold start, physically observed reuse and modeled reuse distinct. The 690 kbps cold-start result on Nadal–Kyrgios and the modeled 19.24 kbps player win on Alcaraz–Hurkacz belong in different panels.
2. **Close the ball’s machine-task comparison and the reference motion check.** For detection, score the actual decoded pixels with an independent judge, report visible-frame recall, localization tolerance and false positives on absent frames. A missing tile retains the native ball if the base contains it. Use the player-task and court studies to explain observed effects and decide whether a new channel is worth its bytes.
3. **Freeze the selected modes and validate on unopened matches.** A bandwidth ceiling can select among measured complete streams. An operational adaptive-bitrate (ABR) policy must make the choice using information available before playback and pay for switches, initialization, model/reference updates and fallbacks. Measure it against always-AV1, always-ROI, always-DCVC and the best single fixed policy on the same passages. Report uncertainty by physical match.
4. **Write to the supported captions.** The multi-match tracked-ball result and scoped player result can stand individually. A combined foreground headline requires the shared-objective comparison and held-out confirmation. Show empirical operating ranges. Rackets enter the headline only when independently evaluated; other sports and viewer studies follow a concrete claim. Check figure permissions, author approval and venue requirements before submission.

## Working from figures

For a paper experiment, name the panel and draft its caption first. Specify the missing row or point, metric and denominator, rate accounting, comparator and the decision the result would change. Look up existing receipts before running anything. Add the new result, including an unfavorable result, to that panel’s evidence file and regenerate its figure. Experiment records own detailed methods, job IDs and budgets; this page owns the order of work.
