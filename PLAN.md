# PointStream paper figures

PointStream splits a broadcast at scene cuts. On suitable shots, the sender can describe foreground motion with points and transmit appearance where needed. Other shots use a conventional codec. The research question is which representation makes the best use of a given bandwidth budget for a viewer or a machine. Keep system design general. Tennis provides the principal evaluation.

## Manuscript sequence and figure priority

Lead evaluation with **two separate rate–quality figures**, one for all players and one for the ball. Put total delivered bitrate on x and the same regional metric on y. Target 20, 50 and 125 kbps, plot actual rates, and preserve higher-rate outcomes to show the boundary of any gain. Use only the common measured support when pooling curves. Average people within a shot, shots within a match, then weight physical matches equally; for historical union-mask scores preserve their original regional definition. Show match observations and training exposure. Use a near/far split as a diagnostic only if a prespecified scale effect persists across matches. Do not pick a different winning rate for each test match.

## Twelve-hour run order

The November 21–22 campaign runs from 21:24 to 09:24 UTC on campus. The order below gives each figure’s decision and evidence. The receipt for each run records its shorter limit.

1. **Populate the low-rate figures.** Audit the stage/source/metric contracts of the nine historical player windows and three ball matches. Run the [Alcaraz native controls](docs/experiments/starved-joint-20261122/README.md). Run a [real fixed-budget tracked-ball comparison](docs/experiments/starved-rally-tiles-20261122/README.md) on the source-reviewed rally with its actual native sidecar. Rank against compatible controls. Freeze settings on development and repeat on different matches before claiming generality.
2. **Explain the complete player cost.** Run the [quarter-scale base and player recomposition](docs/experiments/starved-base-local-20261122/README.md). Reuse authenticated poses, rendered players, mask outputs and ball packets. Contrast a lower ongoing cost with paying for appearance at start. Use shared motion-reviewed reference settings; add a valid measured warm return and held-out players before claiming an operational gain.
3. **Close the starved machine comparison.** On the separate [292-frame ball detection passage](docs/experiments/ball-matched-low-20261122/README.md), match transmitted bytes before applying the frozen detector. Compare recall and false detections, with the prior 63.06/64.08 kbps result retained. Then run the [segmentation pilot](docs/paper/figures/player-tasks/README.md) on truly comparable decodes. Pose accuracy requires human joint labels.
4. **Test the conventional reuse explanation.** Use [native AV1 with an explicit cross-cut reference](docs/experiments/native-return-control-20261122/README.md). Compare first at identical reference and coding settings on the source-only development derivative; only a common native-resolution end-to-end comparison could establish superiority over conventional reuse.
5. **Prepare the starved visual and confirmation.** Freeze source contact and actual overlapping decoder outputs. A frozen joint mode should be compared with AV1, effective ROI and DCVC on unopened matches. Preserve common support, all delivered frames, startup/reuse costs and temporal assessment. Avoid additional demonstrations until the two lead figures have their comparison.

## Working from figures

For a paper experiment, name the panel and draft its caption first. Specify the missing row or point, metric and denominator, rate accounting, comparator and the decision the result would change. Look up existing receipts before running anything. Add the new result, including an unfavorable result, to that panel’s evidence file and regenerate its figure. Experiment records own detailed methods, job IDs and budgets; this page owns the order of work.
